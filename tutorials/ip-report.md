# 怎么读一份 IP 与风险报告

本教程适用于 0.2 的默认与可选增强报告。默认免 Key 检查提供归属、代理标签、
ProxyCheck/IPQuery 原始风险分和 StopForumSpam 记录，以及浏览器网络观察。
IPQS、AbuseIPDB 和 ipapi.is 的额外数据由用户自行选择、配置；未配置不影响默认结果。
DNS 使用单独的 [解析器观察](dns.md)，不能替代实际浏览器 DNS。
以下表格说明解释方法；未启用的来源不会凭空出现测量结果。

## 先看这是谁的结果

报告默认先回答三个问题：**现在发现了什么、需不需要处理、下一步做什么**。
首页是一张三列表格：**检查项｜结果｜建议**。测量结果使用“通过 / 需注意 / 未完成”；IPv6 策略使用“通过 / 建议关闭 / 待确认”，
网络连接、IP 信誉、历史记录和本次浏览器检查逐项列出；未完成的检查不会显示为通过。
IPv6 默认建议关闭专用环境的出站；未确认时显示操作建议，确认配置后才显示通过。见 [IPv6 操作教程](ipv6.md)。
想核对原始分数、ASN、国家代码、数据源或请求端点，再展开“查看检测依据与技术详情”。

浏览器、终端、远程 Agent 和容器可能使用不同网络。报告必须写明观测来自哪个上下文、
访问哪个端点、使用 IPv4 还是 IPv6，以及时间。只有条件可比，才讨论路径是否变化。
用远程服务器的出口替自己浏览器作判断，会在第一步就看错对象。

## 将测量、数据库标签与账号提示分开读

- “这次请求使用了某个 IP”是测量事实，范围仅限该请求。
- “某供应商标记为住宅代理”是它的数据库结论，需要看方法、日期和观察窗口。
- “官方页面要求完成验证”是用户提供的产品提示，应按照相应流程处理。

这三种信息可以帮助排查，但不能相互替代。一个 IP 分数不能解释所有登录或付款问题。

## 遇到这五种情况怎么办

| 情境 | 正确读法 | 下一步 |
| --- | --- | --- |
| 同一 IP 在两个来源分数不同 | 分数定义、输入参数、观察窗口或样本可能不同 | 看来源解释和请求配置，不取平均、不挑最低分 |
| 标签写 ISP，但又有住宅代理标记 | 网络归属与使用行为是不同维度 | 查看代理标签依据和时间；不据此断言用户欺诈 |
| 没有举报 | 在该来源和观察窗口内未发现记录 | 保留覆盖范围，不写成“绝对安全” |
| DNS/WebRTC 与 HTTPS 结果不同 | 不同协议路径可能不同，也可能有正常分流、共享出口或隐私机制 | 先确认预期，再检查对应配置；没有结果也不代表不存在差异 |
| 更换设置后操作成功 | 配置、时间、重试、验证状态都可能参与变化 | 保存前后条件与结果，只把已复查的问题写成解决 |

## 有问题时，按范围处理

浏览器能力问题先核对实际站点权限；网络问题先核对路由意图与受影响的客户端。
官方资格、验证、付款和账号限制走对应官方流程，保留必要的脱敏提示。
不要仅凭一个外部标签购买新环境或反复更换设置。

## 使用 Agent 辅助

安装 [Skill 与检测核心](skill.md) 后，可以这样说：

> 使用知彼，先检查你当前运行环境的网络配置。告诉我哪些结果属于你的进程，
> 哪些还需要我的浏览器结果。解释发现的问题和未测项目。

当前可调用能力以 `zhibi capabilities` 为准。增强情报只有接入并启用后才能使用；
模型不能用自己的推测补齐缺失分数或数据库记录。

## 将实践写成教程

每个案例记录产品、阶段、时间、真实背景、观测来源、所做操作与后续结果。
把事实、个人解释和还待验证的假设分开。成功案例与失败案例使用同一模板，
并保留正常反例、观察时长和缺失信息。

发起人的三个成功注册案例等待本人补充真实过程，参见 [作者教程](author/README.md)。
分享前删除账号标识、Cookie、令牌、支付材料、完整 IP 与可识别截图。
