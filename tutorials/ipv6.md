# 专用环境默认关闭 IPv6 出站

**不需要 IPv6 时，知彼默认建议关闭专用环境的 IPv6 出站。**
目的是减少未受代理或路由规则控制的出口。这是本项目的网络隐私策略，不是 目标服务 官方防封要求。

## 照这三步做

1. **确认作用范围。** 找到实际使用的浏览器环境，以及它所用的代理客户端、专用虚拟机/容器或出口防火墙。只调整这个环境；不要默认关闭整台日常电脑的 IPv6。
2. **关闭出站并使设置生效。** 如果代理客户端提供 IPv6 出站控制，按该软件文档禁用；否则在专用环境的出口规则中阻断 IPv6 出站。保存配置，重启该环境。仅选择“优先 IPv4”、屏蔽 AAAA 记录或者关闭 WebRTC，都不能代替这一步。
3. **核对配置，再复测。** 确认禁用/阻断规则确实覆盖这个环境，保存设置截图或生效配置，再让 Agent 在同一环境检测。测不通只是一条观测，不能单独证明关闭成功。

可以直接告诉 Agent：

> 按知彼的默认 IPv6 策略，检查我的专用环境应该在哪里关闭 IPv6 出站。给我具体步骤，完成后核对生效配置并更新报告。

**AdsPower 用户：** 先核对该配置实际使用的代理和出口。不能把 WebRTC 的“禁用”当成 IPv6 已禁用，
也不能假定每个版本都提供独立的 IPv6 开关。如果当前软件无法仅限制这一环境，应先确定专用虚拟机、
容器或独立出口等可控范围，别直接修改整个宿主机的网络。

## 报告怎么看

| 检查项 | 结果 | 建议 |
| --- | --- | --- |
| IPv6 出站策略：已核对禁用/阻断配置 | 通过 | 保持当前专用环境配置 |
| IPv6 已连通，尚未实施默认策略 | 建议关闭 | 在专用环境关闭 IPv6 出站，保存并重启后核对 |
| 尚未取得配置确认，包括检测超时 | 待确认 | 核对代理客户端或出口防火墙的禁用配置，不能仅凭请求失败判断 |

“通过”记录的是本次、这个环境的配置核对，不是对所有网络路径的永久保证。
更换浏览器环境、代理或出口规则后，应重新检查。确实需要 IPv6 的用户，可以采用单独验证的双栈方案；
它不属于本项目默认的“关闭 IPv6”路径。

## Agent 怎样把“已确认”写进报告

普通用户让 Agent 完成即可。Agent 先核对真实设置，保留本地配置证据；在一份新检测生成后的十五分钟内运行：

```bash
python3 <Skill目录>/scripts/zhibi.py confirm-ipv6 <本次检测目录> \
  --evidence <本地设置截图或配置文件> \
  --configuration blocked --method local_config --reviewed \
  --out <新的确认报告目录>
```

`disabled` 表示已禁用，`blocked` 表示出站被规则阻断；通过设置界面核对时使用 `--method settings_ui`。
`--reviewed` 表示操作者已经核对配置，不是脚本自动判断。命令只记录证据摘要并生成新报告，
不会替你关闭 IPv6，不会联网，也不会上传截图或配置。若同一次检测仍有 IPv6 成功结果，确认会被拒绝，需修正后重新检测。

不要拿一张请求失败截图来确认配置，也不要把此确认复制给另一个环境。原始检测和证据保留在本机。

依据：[RFC 7359 的双栈流量绕过说明](https://www.rfc-editor.org/rfc/rfc7359.html)；
[微软关于避免普遍禁用系统 IPv6 的说明](https://learn.microsoft.com/zh-cn/troubleshoot/windows-server/networking/configure-ipv6-in-windows)。
