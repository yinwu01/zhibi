# 边界与声明纪律

## 三条红线

1. **不提供绕过地区限制或规避风控的能力。** 地区不符属于合规问题，结论是停止，没有技术方案。
2. **不推荐、不返佣、不销售**任何 VPS、代理、指纹浏览器或服务。搜索结果里出现商家，不要把商家名写进结论。
3. **不代装、不代搜、不改写**用户的启动命令。命令由用户提供，原样使用。

## 声明纪律

**每条能力后面必须紧跟一句"它不覆盖什么"，并且要指向用户真正会推错的那一步。**

| 我们说 | 必须补一句 |
|---|---|
| 未发现异常 | 未发现不等于通过；没测也不等于通过 |
| 检查在本机完成 | 查询 IP 情报时，对方仍然看得到被查的地址 |
| 时间已经调好 | 只对这台服务器生效，不影响别的机器 |
| 浏览器已经配好 | 只表示这次测到的项目一致 |
| 全部通过 | 只表示这个工具测的那几项，不保证任何服务端的结果 |
| 命令在后台跑着 | 表示进程在跑，不表示它连得上任何服务 |

## 判读三分法

任何一项发现，必须先归类，再决定下一步：

| 类型 | 判据 | 下一步 |
|---|---|---|
| 技术问题 | 机器或配置造成，能测、能改 | 先留快照，改完重新测 |
| 渠道问题 | 出口类型、地区归属造成，本机改不了 | 说明这是渠道限制，给出选项，不推荐商家 |
| 合规问题 | 地区不支持、条款禁止 | **停止**，明确说改配置解决不了 |

## 一项发现要成立，必须同时满足

- 有一个看得到的对象
- 有来源和时间
- 有实际的后果
- 有复查的条件

只有观察值、没有后果和复查条件的，写成"背景信息"，不写成"发现"。

## 不做的判断

- 不从测量结果推断账号状态、资格或结果。
- 不把服务商给的分数当成上游的规则。
- 不因为语言、时区、字体这类观察单独建议改动。
- 不把同一出口的多个使用当成同一个账号。
