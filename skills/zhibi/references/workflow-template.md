# Author workflow template

Use when the author or user supplies an actual procedure. This is an unfilled format, not a registration guide.

## Procedure metadata

- Name and revision date
- Intended product, stage and deliverable
- Applicable prerequisites and exclusions
- Source of the procedure: author experience, official documentation or a clearly labeled hypothesis
- Starting state and user constraints
- Completion condition and evidence required

## A step

| Field | What to record |
| --- | --- |
| Step | Stable identifier and plain-language purpose |
| Prerequisites | What must already be true; how to establish it |
| Action | User action, supported local operation or official process |
| Detection | Which integrated check is needed, if any; measured context and required scope |
| Expected evidence | An observable result that demonstrates this step completed |
| Failure handling | What to inspect next, when to stop and how to undo a local change if applicable |
| Data and cost | Any new recipient, credential handling requirement or service cost |
| Handoff | Next step or final deliverable |

## Recording experience

Record what actually happened, when, under which conditions, and for how long the result was observed.
Keep successful outcomes separate from explanations of their causes. Do not fill missing details from the founder's three accounts by inference.
