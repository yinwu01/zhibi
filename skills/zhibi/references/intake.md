# N1 受理：只问两件事

用户来的时候，你只需要拿到两个输入。

| 输入 | 例子 | 缺了怎么办 |
|---|---|---|
| 要长期跑的命令 | `codex`、`pi`、任意可执行命令 | 问一句："你打算在服务器上跑什么命令？" |
| 服务器怎么连 | 地址、用户、端口、登录方式 | 问一句："服务器的地址和登录方式是什么？" |

## 不要问的

- 不要问用户"要不要用代理""用哪家 VPS""想伪装成哪个国家"——这些是用户在准备阶段自己定的，不在本流程内。
- 不要问用户的技术水平、使用目的、账号情况。
- 不要替用户选服务、选商家、选地区。

## 拿到之后立刻判断

**服务器连得上吗？** 连不上 → 说"我连不上这台服务器，先确认地址和登录方式"，停下，不要进入下一步。

**命令是用户自己给的吗？** 是 → 原样使用。不是（用户说"你帮我挑一个"）→ 说明："命令需要你自己提供，我不替你选。"

**这台服务器之前被本工具配置过吗？** 已经有一套配置 → 先读现状，再给出"要不要更新"的计划，不要直接覆盖。

## 只有一条路径可以降级

服务器连不上、或者用户暂时没有服务器 → 只能做本机部分（N2 → N6 → N8），并在交付物里明确写：**本次没有服务器，远端未验证**。不要把"只有本机"写成"环境已就绪"。

## 受理完成时，对用户说一句人话

> 我拿到两样东西了：你要跑的命令，和服务器怎么连。接下来我先看看两边的现状，然后告诉你要改什么——你点头我再动手。

然后进 N2。
