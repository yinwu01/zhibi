# N3 / N5 / N7 远端：看、改、验

三个动作对应三条命令，全部默认只出计划，`--apply` 才动手。

## N3 看（`check`）

读六项：系统、时钟准不准、时区是什么、系统语言是什么、用的哪个地址解析服务、还有多少资源。

对用户只说一句结论，例如：

> 服务器时间对得上，语言和时间是 UTC（格林尼治时间），解析用的是公共 DNS。这台机器现在看起来像一台"哪都不属于"的服务器。

## N5 改（`build`）

**改之前先留一份现状快照。** 没有快照不允许改。

改动只有三类，每一类都要给回滚命令：

| 改什么 | 为什么 | 回滚 |
|---|---|---|
| 时间（时区） | 让机器认为的时间和它所在的地方一致 | 改回原来那个时区 |
| 语言（locale） | 让系统和程序的默认语言与地区一致 | 保留原值，不强制覆盖 |
| 常驻（systemd） | 让用户给的命令在后台一直跑、关机重启自己起来 | 停用并删除这份配置 |

**不改的**：不代改服务器的 DNS（让用户用云厂商控制台自己设，改完回来验）；不动防火墙；不装任何软件。

**用户给的命令原样写进配置**，一个字都不改、不补全、不包装成别的样子。

给用户的话：

> 我要做三件事：把时间调到和服务器所在地一致、把系统语言对上、让你的命令在后台常驻。改之前我会留一份原来的记录，随时能撤回。要不要开始？

## N7 验（`accept` 的远端一半）

| 项 | 算通过的条件 |
|---|---|
| 命令在跑 | 进程当前是运行状态 |
| 重启自起 | 服务已设为开机启动 |
| 时间 | 与目标时区一致 |
| 语言 | 与目标语言一致 |
| 时钟 | 系统时间已同步 |
| 解析 | 不是公共 DNS |

**每一项只有四个状态**：通过 / 已改但没验证 / 不通过 / 没测。没测的不许说成通过。

## 失败时

- 命令起不来：读日志，把**具体的错**用一句话说给用户，例如"启动失败，报错说找不到这个命令——可能是还没安装"。
- 服务器上没有 systemd：`这台服务器没有后台常驻的机制，程序断开就会停，换成别的方式我做不到。`
- 连接中断：记住已经做完的节点，重连后从那一步继续，不重跑。

## 密钥与地址

只在本机使用，不上传、不外发、不写进报告和日志。报告里只出现服务器地址和公钥指纹。
