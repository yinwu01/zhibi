# 浏览器接入

先询问是否使用指纹浏览器及具体品牌。支持 SOCKS5 的浏览器可以使用 `connect` 提供的 `127.0.0.1:10818`，端口以本轮实际参数为准。浏览器在别的机器上时不能使用此回环地址；在那台机器启动连接或另行设计经过授权的接入。

优先使用用户已有配置。保存原代理设置；按浏览器实际能力选择 API、界面操作或用户自行填写。没有某品牌 API 不代表不能接入；不能因此承诺所有品牌都已经验证。HTTP-only 客户端需要另行准备协议适配器，不能把 SOCKS 端口冒充 HTTP。

域名解析应通过所选代理，检查具体浏览器的 DNS/DoH 配置。SSH SOCKS 不提供 UDP 转发；依据浏览器支持的选项配置 WebRTC，再实测。没有候选或请求失败只说明本次没有可比结果，不证明没有泄漏。

不要求本地浏览器伪装成 Linux，也不机械照抄服务器语言。仅按用户选择的合理目标配置时区/语言。是否重启以配置生效条件为准，修改后重新读回并在该浏览器打开探针。

使用 `session --preset basic --network` 获取新结果，必要时显式选择深入网络检查。确认实际出口符合预期，再由用户完成所需网站的正常登录。网页能打开、登录成功和网络路径验证分别记录。断开时恢复原浏览器代理，停止自己启动的隧道，检查普通联网恢复。

## 创建专用 Chromium 配置

用户选择直接启动 Chromium 系浏览器时，用 `browser-workspace --browser-binary 可执行文件 --local-port 10818 --out 新目录` 创建独立环境。默认不导入历史、Cookie 或扩展；限制定位、摄像头、麦克风和通知，关闭扩展与同步，设置 SOCKS5 和 WebRTC 非代理 UDP 限制。运行生成的 start-browser.py 后再执行 session。需要通话/录音/定位时，按目标站点实际用途允许权限并复测。

该入口不编辑 AdsPower 等管理器的内部配置；已有指纹环境按管理器 API/界面设置同等控制。四项权限在真实 Chrome 上使用页面权限查询进行验证，其他衍生浏览器仍需同样读回。
