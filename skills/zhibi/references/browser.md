# N6 / N8 本机指纹浏览器

目标只有一个：**本机浏览器和服务器看起来是同一台机器**。

要对的四项：时间、语言、网络通道、以及一条会把真实位置漏出去的便道（WebRTC）。

## 先读服务器的读数，再决定浏览器填什么

不要凭猜。N3 已经拿到服务器的时区、语言、出口，直接照抄：

| 浏览器字段 | 填什么 |
|---|---|
| 时区 | 服务器的时区 |
| 语言 | 服务器的系统语言 |
| 代理 | 指向服务器 |
| WebRTC | 不许直连本地，必须走同一条通道 |
| UA / 平台 | 与服务器系统一致的方向，不要跨平台乱填 |

## 三档操作

| 档 | 判断条件 | 做法 |
|---|---|---|
| **自动** | 浏览器本地 API 已开启 | 直接写配置，一次都不点 |
| **半自动** | API 没开，但宿主能操作界面 | 用 computer use：打开浏览器 → 选中要用的环境 → 编辑 → 填时间和语言 → 保存 → **关掉再重开** → 读回读数 |
| **手动** | 宿主不能操作界面 | 只交接这一步：给一张"哪个框填什么"的对照表，等用户做完，回来继续 N8 |

**关掉再重开是必须的**：很多设置只在浏览器启动时生效。重开之后必须重新读一次读数，不能因为"我改了"就认为"生效了"。

## 默认用 AdsPower

用户没有指定别的，就按 AdsPower 走。用户想用别的品牌，按上面三档自己发挥即可——不要评判哪个更好，也不要推荐。

## N8 验什么

| 项 | 算通过的条件 | 不通过时怎么说 |
|---|---|---|
| 时间 | 浏览器认为的时间和服务器一致 | `浏览器的时间还是本地的，需要重开一次浏览器。` |
| 语言 | 浏览器上报的语言和服务器一致 | `浏览器语言没对上。` |
| 网络通道 | 浏览器看到的对外身份 = 服务器 | `浏览器没有走服务器那条通道，流量还是从你本地出去的。` |
| 便道（WebRTC） | 没有暴露本地网络的痕迹 | `浏览器有一条便道漏了你本地网络的位置，需要在设置里关掉。` |

任一项不通过 → 回 N6 改，改完重新验。不通过不许进 N8 交付。

## 说人话的例子

> 浏览器这边好了：它现在认为自己在服务器的那个时区、说同一种语言、上网走的是服务器那条通道，也没有再把你的本地位置漏出去。

> 还差一项：浏览器的时间还是你本地的，因为设置要重开才生效。我把浏览器关掉重开一次，然后再测一遍。
