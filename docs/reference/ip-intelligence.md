# 本地 IP 与欺诈风险检测：原理、对标和交付标准

核对日期：2026-10-19。本文保留原始设计；已接入 IPWhois、ipapi.is、IPQS、AbuseIPDB、ProxyCheck v3、IPQuery、StopForumSpam 和高级双栈/WebRTC 探针。
下表同时保留目标与当前覆盖；验证见 [验收](../architecture/validation.md)，不是准确率评测。
已对选定免费来源执行真实 IP 查询；没有使用用户的付费密钥，也没有读取账号凭据。

第一项交付要回答：这次连接从哪里出去、情报库如何描述该 IP、有哪些带时间和来源的风险线索、
哪些结果存在分歧，以及下一步该检查什么。0.2 已接入七个来源及浏览器路径测量，未覆盖项继续明确保留。
免 Key 的四源组合已在真实 AdsPower 出口实测；结果不等于账号注册成功率。接入与费用以 [供应商教程](../archive/tutorials/providers.md) 为准。

## 检测网站背后的三个部分

1. **实际测量**：服务器读取当前连接来源地址；浏览器通过不同端点、地址族与协议产生测量。
2. **情报查询**：将测得的 IP 查询地理/网络/代理/滥用数据库；数据库依靠各自的采集网络与历史记录更新。
3. **解释与呈现**：展示标签、评分、来源和处置建议。供应商评分含义及查询参数可能不同。

“本地检测”指采集协调、分析与报告在用户设备运行。公网出口测量仍需要远端观察者；
实时欺诈情报通常需要供应商 API，或者用户依法取得的本地数据库。
一份 HTML 和本地脚本无法凭空重建全球欺诈样本与商业模型。

## 具体对标什么

下表以官方文档和开源仓库为依据。它是能力对照，不是“最先进”排名，也未证明哪家对 目标服务 更有效。

| 对标对象 | 公开方法或能力 | 知彼借鉴什么 | 不能直接推导什么 |
| --- | --- | --- | --- |
| [IPCheck.ing](https://ipcheck.ing/tools/) | 多来源双栈出口、WebRTC 与 DNS 测量等 | 区分协议路径和数据源；保留失败与不同观测 | 多个端点结果不同，不自动证明泄漏 |
| [xykt/IPQuality](https://github.com/xykt/IPQuality) | 多数据库 IP 类型、风险评分、风险因子及服务测量 | 并列呈现多源结果和可导出报告 | 邮件黑名单、流媒体可达性不能充当 目标服务 注册结论 |
| [IPinfo Extended](https://ipinfo.io/developers/privacy-extended-api) / [Max](https://ipinfo.io/developers/max-api) | 代理类型、直接观测与推断、置信信息、时间窗；住宅代理活动字段 | 显示标签的证据方法、最近观察时间与范围 | ISP 网络不等于普通住宅用户；供应商标签不等于恶意 |
| [IPQS 响应字段](https://www.ipqualityscore.com/documentation/proxy-detection-api/response-parameters) | 代理、近期滥用、活动强度与原始评分 | 同时解释评分因素、查询配置和缺失字段 | IP-only 查询不能冒充完整用户或交易评估 |
| [Scamalytics v3](https://docs.scamalytics.com/ip-fraud-risk-api/v3/) | 自有欺诈信号及多个上游情报源 | 展示原始分数、上游来源与套餐覆盖 | 同一上游出现在多个服务中，不构成独立多数票 |
| [AbuseIPDB](https://docs.abuseipdb.com/) | 滥用举报、时间窗口、不同举报者数量与置信评分 | 区分举报类型、时效和证据规模 | 无举报不等于无风险；服务器攻击举报不等于账号欺诈 |
| [MaxMind Anonymous IP](https://www.maxmind.com/en/geoip-anonymous-ip-database) / [minFraud](https://dev.maxmind.com/minfraud/api-documentation/responses/) | 匿名网络数据库与交易风险服务 | 区分网络标签与交易评分；支持依法取得的本地数据库路线 | 不能用缺少交易上下文的 IP 查询复现完整交易风险 |

Ping0 搜索索引曾展示其 FAQ 关于历史攻击与滥用打分的说明，但本轮直接打开 FAQ 未取得可审查正文；
不据此复述其具体算法、比较准确率或确定接入方案。

借鉴原理不等于复制代码或抓取免费网页接口。尤其 xykt/IPQuality 使用 AGPL-3.0，
当前知彼采用 MIT；若将来引入其代码，要单独处理许可证兼容和分发要求。

## 第一版增强检测的必需模块

| 模块 | 要输出的事实 | 实现原理与边界 | 0.2 覆盖 |
| --- | --- | --- | --- |
| 双栈与上下文 | 浏览器/Agent 出口、IPv4/IPv6、端点、时间、执行位置 | 各上下文向明确端点请求；只比较相同地址族、端点和可比时间窗口 | 已接入双栈探针与受约束比较；跨系统实机验收另记 |
| 网络身份 | 国家、ASN、前缀、组织、网络类型；来源分歧 | 地理库/ASN/RDAP 等授权数据，区分注册资料和实际网络定位 | 已接入国家、ASN、组织与类型；前缀实体关系尚待补 |
| 匿名网络与住宅代理 | VPN、Tor、托管、中继、住宅代理标签；方法/首次与最近观察/窗口 | 授权代理情报；字段随供应商与套餐变化，未提供时保留未知 | 已接入相关字段；住宅代理的独立细分类与活动窗口未覆盖 |
| 欺诈与滥用 | 供应商原始分、近期滥用类别、举报数、不同举报者数、观察窗口 | 授权信誉数据；保留原始语义和查询参数 | ProxyCheck/IPQuery 风险分、StopForumSpam 记录已实测；IPQS/AbuseIPDB 待用户自有免费或付费 Key 的现场验证 |
| DNS 实际路径 | 测试时递归解析器的来源、时间与测试域名范围 | 唯一测试子域 + 受控权威 DNS 观测与短期结果关联 | 已提供 dig 默认解析器观察；唯一子域权威关联与浏览器 DNS 仍未覆盖 |
| WebRTC 路径 | ICE 候选类型、可见地址与 HTTPS 出口的关系 | 浏览器 ICE/STUN；区分 host、srflx、relay 与 mDNS，缺失结果不当作安全证明 | 已接入，保留失败、mDNS 与自动化上下文边界 |
| 来源与时效 | 查询时间、源更新时间、观察窗口、参数、套餐、上游依赖 | 标准化供应商响应；缺失、过期、限流和分歧分别显示 | 已接入参数、查询时间、窗口及已声明的上游依赖；供应商未返回的时间保留未知 |

**增强版第一项交付的最低标准**：完成多来源网络身份对照，至少接入一个具有明确欺诈语义的情报源，
再接入一个互补的代理或滥用来源；具备来源/参数/时效解释与失败处理。
DNS、WebRTC 是独立验收模块；未通过前报告必须显示未覆盖。
“查到 IP + ASN”不能作为该项交付完成的标志。

## 高级能力为什么更有价值

### 同一个分数，需要知道是怎样查出来的

IPQS 的 [Advanced Options](https://www.ipqualityscore.com/documentation/proxy-detection-api/advanced-options)
公开了严格程度、公共网络处理、可选设备信息等设置，也说明网页查询使用特定参数。
因此，同一 IP 的网页分数与 API 分数不同，可能源于请求配置。

知彼保留准确的请求配置与所发字段。默认不发送 User-Agent、语言、用户 ID 或交易资料；
可选扩展必须说明新增数据。不能为了得到更低分数反复调整查询条件或冒填设备类型。
返回 false 的字段也需检查其前提；缺少必要输入时不能解释为完成了相应检测。

### 情报的时间是特征本身

IPinfo Max 的住宅代理活动字段有明确观察窗口，Extended 提供观测/推断及置信信息。
数据库更新日期、最近活动日期与我们查询的日期是三件不同的事，应各自保存。
只有供应商返回这些字段时才展示，不能用“刚查到”代替“数据很新”。

### 多来源需要处理依赖

Scamalytics 的 v3 文档列出包括 IPinfo 在内的外部来源；AbuseIPDB 文档也标明部分网络资料来自 IPinfo。
因此知彼在图中记录“谁提供”和“上游来自谁”。地理位置相同可能只是共享数据库，不能反复增加置信度。
多个分数不做算术平均，不转成“账号处置概率”。

### TLS/HTTP 指纹放在后续观测模块

[Cloudflare JA3/JA4 文档](https://developers.cloudflare.com/bots/additional-configurations/ja3-ja4-fingerprint/)
说明这些特征来自 TLS 连接握手。普通页面 JavaScript 不能等价复现服务器看到的握手；
需要合适的受控远端观测端点，并验证中间层是否改变了测量。
即使测得，也只描述到该端点的连接，不能宣称读到了 上游服务商 内部的判定。
因此第一版不把 JA4 当必选项，更不以修改指纹作为默认操作。

## 第三方服务与本地部署

| 路线 | 能提供什么 | 需要什么 |
| --- | --- | --- |
| 基础版 | 本地配置、已实现的浏览器能力；可选公开出口/归属查询 | 本地运行；启用公网请求时披露接收方 |
| 增强版 | 多源代理、信誉、欺诈相关情报 | 用户自己的服务凭据与相应套餐；逐来源预算和请求上限 |
| 离线情报版 | 已下载数据库覆盖的网络身份与风险标签 | 数据许可、更新机制、版本与过期提示；无法离线测出当前公网出口 |

优先评估 **IPQS + 一个互补来源（IPinfo / AbuseIPDB / 授权本地库）**。
这是接入顺序建议，不是效果排名；正式选型还需要样本验证、价格与许可核对。
IPQS 文档支持 Header 凭据，可避免把 Key 放进浏览器文件和 URL。
Scamalytics 本轮核对的 API 文档使用 URL 凭据，与本仓库现有凭据边界不匹配；
先评估其本地数据库或更合适的鉴权方式，不为凑供应商数量放宽边界。
部分高级字段只在特定付费套餐开放；不能把示例响应当成免费版能力。

本地核心负责鉴权、查询、缓存与标准化；前端文件不内嵌服务密钥，Agent 不读取密钥。
后续一键本地应用需要把服务绑定到 loopback，限制 Origin/Host、使用会话令牌，不能成为任意 URL 转发代理。
这是后续包装设计；当前 start.html 仍是基础版单文件入口。

DNS/STUN 观测还需要服务端基础设施，可以选择合适的外部服务或自建。
自建可控制日志与保留时间，但仍有运营成本，也不等于拥有全球欺诈数据。

## 报告与 Agent 摘要的目标格式

每份结果要能回答：测谁、在哪条路径测、查了哪家、数据多新、为什么提示、下一步是什么。

供应商记录至少包含：

```text
subject_context / measurement_id / address_family
provider / product_tier / upstream_sources / query_profile
queried_at / source_updated_at / observation_window / first_seen / last_seen
status / labels / original_score / score_semantics / evidence_method
```

这些是规格字段，尚不是当前 report schema。原始 IP 只进私人报告；
模型摘要使用去标识的主题、状态与解释，不附凭据、供应商自由文本或完整响应。
不能把新字段直接塞入现有严格 Schema 而绕过校验。

示意输出（合成情境，非真实查询）：

```text
网络身份：两个数据源的 ASN 一致；其中一个为转载来源，非独立确认。
代理情报：一个来源标记住宅代理，附最近观察日期。
滥用记录：本次来源查询超时，当前未知。
路径检查：浏览器 IPv4 已测；Agent IPv6 已测，两者不可直接比较。
下一步：先在可比条件下复测路径；核对情报时效。此报告没有账号处置结果。
```

## 第一版的验证标准

- 实现：用固定响应与故障场景验证缺 Key、套餐缺字段、超时、限流、版本变化、陈旧缓存与来源冲突。
- 隐私：记录出站接收方和字段；测试凭据不进入 URL、页面、日志、异常、模型摘要或分享结果。
- 测量：在已知的正常双栈、企业共享网络、有意分流等环境确认实际路径，保留无法测量的状态。
- 对标：对同一授权样本、相近时间和相同查询参数对照供应商原始响应，记录字段覆盖、耗时、费用及差异。
- 效果：有独立真实标签时才计算准确率/误报率；多个供应商彼此同意不能充当真值。
  目标服务 注册结果需独立记录条件与观察窗口，不用供应商评分充当注册结果标签。

第一版不复刻商业检测模型，也不宣布“最先进”。目标是接入可用的先进情报，
把测量、来源与解释做得可验证，让用户知道每项结论的根据。
