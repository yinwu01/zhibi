# 自建浏览器 DNS 权威观测（可选）

用途是实测“这个浏览器发起的随机域名，经哪些递归解析器到达你控制的权威服务器”，并查看上游是否带 ECS。服务器看不到浏览器到递归解析器这一段是否使用 DoH，因此不能由观测结果断言 DoH 已开启或“绝无 DNS 泄漏”。

需要自己拥有的域名、可接收 TCP/UDP 53 的服务器、HTTPS 反向代理与覆盖 `dns.example.org`、`*.dns.example.org` 的有效证书。这些资源和费用由用户自行准备；基础检测不需要。

1. 在自己的域名服务商配置子域委派，将 `dns.example.org` 的权威 DNS 指向自己的服务器。权威 NS 主机名需有正确的地址记录；不能只把随机子域交给别家的通配符解析。
2. 在服务器安装本项目核心，使用自己的真实域名/IP 明确启动：

   ```bash
   python3 zhibi-core.pyz dns-observer --zone dns.example.org --address 服务器公网IPv4 --bind 0.0.0.0 --dns-port 5353 --http-port 8053
   ```

3. 用防火墙/容器映射让 TCP/UDP 53 到达该 DNS 监听端口；HTTP 8053 只供反向代理访问，不直接公开。反向代理为主域及随机子域提供有效 HTTPS，转发 `/ticket`、`/ping`、`/result`。**不关闭证书校验，不跨过浏览器证书警告。**
4. 在实际浏览器打开知彼高级探针，选择 DNS 项，填写 `https://dns.example.org`，运行并保存结果。

核心为每次观测生成 128-bit 随机票据，浏览器请求 `票据.dns.example.org`；HTTP 请求带来的 DNS 查询在权威端关联到该票据。服务器最多保留 128 个票据，5 分钟过期，最多 16 个解析器；只驻留内存，不记录访问日志。服务不递归解析任意域名，区外查询拒绝，支持有界 UDP/TCP DNS。

外部观测端会接触请求 IP、随机域名、解析器 IP 和可用 ECS；如果改用别人托管的服务，应先明确其运营者和数据政策。页面只接受用户填写的 HTTPS origin；票据返回的域必须与该 origin 一致，避免被响应重定向到其他域。

本版本有本机协议/票据/越界拒绝测试，**尚无公开委派域名的生产实测**。没有自己的域名和服务器时，报告给出“需配置”与本教程，而不是把终端 dig 当成浏览器 DNS 测量。完整公共部署需要自行增加运营级限流、并发、监控和证书管理；不要把小型观测服务当作通用 DNS 基础设施。
