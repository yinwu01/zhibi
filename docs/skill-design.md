# Skill 入口设计

状态：Skill 资源和配套 CLI 已实现。入口为 [SKILL.md](../skills/zhibi/SKILL.md)。资源结构与命令链路已本地验证；各宿主自动发现与真实交互仍待验收。

## 触发任务

入口面向 环境准备、具体异常诊断、准备清单、变更后复验及反馈导出。首次使用可以发生在用户没有 目标账号时，因此不依赖 目标客户端 登录作为前置条件。

名称为 `zhibi`。定位描述为“为准备注册或使用 目标服务 的用户安排本地环境检查，解释有来源的结果，生成准备与复验清单；也用于诊断用户主动提供的注册、登录和客户端异常”。不将一般 AI 安全研究、普通软件网络故障或所有风控话题都触发成检查任务。

## 工作流程

1. 读取当前能力清单和用户已给出的上下文，只补充影响当前判断的信息。
2. 显示适用的检查计划与数据流，遵循用户已经选择的服务范围。
3. 调用确定性核心；没有实现、没有依赖或不支持的检查如实报告，不能编造执行结果。
4. 依据结果中的规则与来源解释结论；模型提出的新猜想留在假设栏。
5. 给出下一步、适用前提与复验方式；用户执行变更后再比较快照。
6. 按需生成反馈预览；导出本地文件不会自动向社区投稿。

已有授权范围内的只读检查不重复索要许可。需要新增外部服务、付费或修改系统时，先把具体动作、数据或差异呈现清楚，再按任务授权执行。

## 报告解释的约束

- `error`、`timeout`、`unsupported` 和 `skipped` 不能解释为安全。
- `verified` 只对应明确事实；不能用检测通过承诺不会被封号。
- 观察到地区、语言或网络差异时，先查看正常解释与用户预期。
- IP 归属不能替代用户真实地区或主体资格。
- 平台未公开的内部风险分、关联权重和阈值保持未知。
- 不读取或要求用户粘贴认证材料；发给模型的是经过筛选的摘要。

## 资源与发布

`SKILL.md` 只保留触发范围、必要流程和关键边界；详细报告解释、数据流及特殊诊断放入按需读取的 `references/`。CLI 的确定性实现只有一份，Skill 不维护第二套权重或规则。

发布包内提供可用版本信息和自包含的说明资源。由 `capabilities` 检查核心是否已安装及兼容；不得在用户不知情时执行远程安装脚本。只有在真实入口通过验收后，README 才提供相应安装命令。

## 首批验收用例

| 用户请求 | 预期行为 |
| --- | --- |
| 我还没注册，先帮我看环境 | 无 目标服务 登录也能执行适用检查 |
| 我看到一个 90% 风险分，要换 IP 吗 | 查分数目标和证据，不按百分比直接建议采购 |
| 所有端点都超时了 | 解释无法完成测量，给出可用性排查步骤 |
| 浏览器与 CLI 出口不同，但这是我的设计 | 保留预期分流，不自动要求统一 |
| 能帮我提交案例吗 | 生成并预览脱敏内容；发送需明确任务授权 |
| 网站要我的 Cookies 来查封号风险 | 解释认证材料边界，提供不读取这些材料的检查路径 |

这些仍是宿主行为验收场景；核心代码测试不等同于 Agent 实际行为验收。
