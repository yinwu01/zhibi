# 我想要写在前面的

目标服务 对于中国用户来说，使用一直是一个非常困难的问题。但眼馋于 目标服务 的能力，我们希望能正常使用，但我发现目前很多所谓的检测网站或项目，主要还是依据一些零星的反馈去修修补补。特别是那些反馈监控网站，你完全不知道它把你的数据卖到了什么程度、卖给了谁。

在我开了 3 个并且稳定使用 20x Max 的账号后，私以为我们应该从风控角度去逆向 目标服务 的风控思路，并针对已知策略给出相应举措。

在常规风控视角下，想要使用一个产品，最核心的策略其实就是 **cosplay**：我们需要把自己伪装成 目标服务 允许范围内的正常用户。只要用户画像合理，账号自然能平安度过。

基于这一点来看，目前很多传闻其实比较扯淡。比如有人说输入中文甚至用中文逗号就会导致封号，中文作为全世界使用最广泛的语言之一，如果一旦使用就会被封，那未免太可笑了。其次是改时区，如果有人在 Linux 服务器上修改，或者因为电脑时钟本身出了问题导致时区错乱，这种单纯的时区变化在风控角度也不可能成为合理的判断依据；如果连这都会直接触发风控，那只能说是风控算法的设计缺陷。

碰巧的是，我目前就在字节某面向国际产品风控团队，从风控建模的角度，我们完全可以推演出 目标服务 的风控政策。在明确政策的前提下，我们就可以做到完美的 cosplay，实现知己知彼、百战不殆。

所以在这个项目里，我希望能结合之前优秀项目的经验，整合风控视角与社区反馈，为大家提供一套针对 目标服务 正常注册和使用的完整方案。

本项目主要包含三部分：

1. 完全本地化的 IP 检测：不再把你的珍贵数据泄露给第三方，避免进一步威胁你的注册和使用环境。
2. 风控规避 Skill：提供指导与辅助，帮助你应对 目标服务 的风控策略。
3. 稳定使用实操 Tutorial：基于我本人稳定持有 3 个账号的使用经验整理出的实操教程。对于很多人来说，可能这部分才是更关键的；其余的检测流程直接交给 Agent 即可自动完成。

这就是为什么我们要发起这个针对 目标服务 的项目。
