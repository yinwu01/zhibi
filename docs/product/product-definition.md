# 产品定义

2026-10-20。这份文档定义知彼是什么、不是什么、按什么流程工作。它与 README 冲突时以本文为准；流程与代码冲突时以本文为准。

## 一句话

> 知彼是一个 Agent 原生的**环境判读层**。在用户自备的出口（VPS / 代理）和指纹浏览器之上，完成「搜 · 装 · 配 · 验 · 判」五步，用可追溯的证据告诉用户：环境现在是什么状态，哪些问题能修，哪些必须换路。

## 标定位置

市面上同类项目分两种：**解决出口的**（VPS 部署、订阅分发）和**解决界面的**（指纹浏览器、身份管理）。知彼都不做，只做它们没有的那一段——**判断**。

| | 谁做 | 知彼的关系 |
|---|---|---|
| 出口 | 用户自备，社区项目提供方案 | 只判不推 |
| 浏览器 | 用户自选，Agent 代搜代装 | 只判不推 |
| 身份/账号隔离 | 其他项目 | 不做 |
| **判断** | **没人做** | **只做这个** |

## 不是什么

| 不做 | 原因 |
|---|---|
| 不卖出口：不推荐、不返佣、不代购 VPS / 代理 | 中立性是唯一独占位；有利益在里面就不能做裁判 |
| 不管理账号身份（多账号归档 / 切换） | 功能溢出，且与「只判读」冲突 |
| 不代替注册、验证、付款 | 同上 |
| 不提供规避地区限制或规避风控的能力 | 产品红线 |
| 不承诺「通过」，不推断账号安全 | 只报告实测项；未测量 ≠ 通过 |

## 三个差异化（按强度排序）

1. **判读而非打分。** 竞品给分数和绿勾，然后用户自己猜。知彼给出**技术 / 渠道 / 合规**三分法的结论。
2. **零推荐、零返佣。** 不含推广链接、返佣、付费推荐，不销售任何服务。
3. **可追溯证据。** 每项读数带来源、时间、校验依据；每条采集记录带来源 URL、版本、哈希。

## 项目形态

**一个自包含的 Agent 能力包（Skill Bundle），不是软件产品。**

| 层 | 载体 | 职责 | 绝不 |
|---|---|---|---|
| 决策层 | `SKILL.md` + `references/` | 决定走哪一步、何时停、如何失败 | 不做测量，不存状态 |
| 执行层 | `scripts/zhibi.py` → `assets/zhibi-core.pyz` | 原子能力：测量、导入、生成报告 | 不串流程，不做判断 |
| 界面层 | `assets/*.html` | 采集原始读数 / 呈现结论 | 不接触可信侧命令 |

### 三条硬约束

1. **流程写在 SKILL.md，不写进代码。** 流程若写死在 Python 里，Agent 就退化成调用器，产品也就退化成 CLI 工具。判断权必须留在文档层。
2. **零依赖、零常驻。** Python 3.9+ 标准库，无 pip、无云、不保管账号。
3. **密钥与服务器地址：可以接收，可以本机保存复用。** 用于连接用户自己的服务器；不上传、不外发、不进入任何第三方请求，不写进报告与日志（报告只出现目标与指纹）。若用户直接粘贴到对话里，凭据会进入会话上下文；推荐用本地文件或 ssh-agent 传入。
4. **一次调用一个 session，全落盘。** 目录为 `~/.zhibi/sessions/<id>/`；中断后可恢复，不重跑。最终报告另存到用户可发现的位置（桌面或用户指定路径），不停留在隐藏目录里。

### 分发与前提

- 分发：单个 Skill ZIP 或 `git clone`；开发者可用 `pip install -e .`。
- 前提：Python 3.9+；computer use 由宿主提供，本 Skill 不安装、不授权。没有 computer use 时走降级路径 D1。

## 工作流程

一条串行主线，八个节点，一个闸门。

```
N1 受理 → N2 本机体检 → N3 远端体检 → N4 出计划 ═ G1 用户确认 ═ → N5 远端部署 → N6 本机浏览器 → N7 两端验收 → N8 交付
                                                                        ↑                        │
                                                                        └──── G2 不一致 ─────────┘
```

### 节点定义

| | 节点 | 做什么 | 产出 |
|---|---|---|---|
| N1 | 受理 | 收两个输入：要跑的命令、服务器怎么连 | `intake.json` |
| N2 | 本机体检 | 系统、Python、指纹浏览器、computer use 是否可用 | `local.json` |
| N3 | 远端体检 | 时间、语言、时钟、解析器、资源、对外身份，并给出评分 | `remote-facts.json` |
| N4 | 出计划 | 合成三行摘要：分数、要改什么、浏览器要填什么 | `plan.md` |
| G1 | 确认 | 用户点一次头。**全程唯一必须的确认** | — |
| N5 | 远端部署 | 对齐时间与语言，把用户给的命令交给系统托管 | `remote.json` |
| N6 | 本机浏览器 | 按远端读数反推浏览器参数并写入 | `browser.json` |
| N7 | 两端验收 | 远端与本地逐项对撞，重新评分 | `verification.json` |
| N8 | 交付 | 一个文件夹：说明、HTML 报告、可复现与回滚脚本 | 交付目录 |

串行而非并行：远端先落地，再动本机浏览器，避免两侧同时处于未知状态。

### 评分

体检输出一个 0–100 分和五个分项，权重固定：

| 分项 | 权重 | 看什么 |
|---|---|---|
| 对外身份 | 25 | 家庭宽带还是机房段 |
| 内部一致性 | 25 | 时间、语言、时钟是否与出口地区一致 |
| 泄漏 | 25 | 解析器与浏览器是否漏出真实位置 |
| 信誉读数 | 15 | 情报源给出的分数（可选） |
| 稳定性 | 10 | 程序是否在跑、重启是否自起 |

规则：**未测维度不参与计分，也不当通过；覆盖率低于 50% 不给等级**。分数只描述本次实测项，不代表任何服务端判断。

### 四种状态

每项读数只能落在四个状态之一，不允许合并，不允许缺省：

| 状态 | 含义 | 报告措辞 |
|---|---|---|
| `pass` | 实测匹配 | 通过 |
| `changed_unverified` | 已改动，没有新测量 | 已改动，未验证 |
| `fail` | 实测不匹配 | 不通过（附原因） |
| `not_measured` | 未测量 | 未测量 |

`not_measured` 绝不折叠进 `pass`。「未测量 ≠ 通过」由此落到文件级。

### 判读三分法

| 类型 | 判定依据 | 下一步 |
|---|---|---|
| 技术 | 本机或环境配置导致，可测可改 | 直接修，改后重新测量 |
| 渠道 | 出口类型、地区归属、账号渠道导致，本机改不了 | 走判据与通用流程自救，不推荐商家 |
| 合规 | 地区不支持、制裁地区、条款禁止 | **停止**，没有技术方案 |

### 降级路径（常态，不是例外）

| 降级 | 触发条件 | 做法 |
|---|---|---|
| D1 | Agent 无 computer use | 脚本照测；界面步骤给用户逐步指令，回来继续 S4 |
| D2 | 浏览器只能手动导出读数 | 走 `generic_export` 基座；用户导入文件，Agent 判读 |
| D3 | 用户只想检查、不想改 | 跳过 S3，S4 → S5 |

报告须标明本次走的哪条路径。

### 复查环

S4 不通过 → 回 S3 改 → 再 S4。第二次起生成前后对比，输出「改动前 / 改动后 / 仍不匹配项」。**状态变化不表示风险升降**，此句必须出现在对比结论中。

## 浏览器适配：能力优先

浏览器由用户在 S1 选定，因此适配必须是能力抽象的，不能是按厂商写的。

| 档位 | 覆盖 | 说明 |
|---|---|---|
| `generic_export` | 基座，任何浏览器 | 手动导出 / 导入读数文件 |
| 自动配置 | 增强 | 需浏览器提供本地 API；当前仅 AdsPower |

「已适配 AdsPower」是**能力陈述**，不是推荐。用户在 S1 看到的是运行时生成的判据对照表，不是固定推荐列表——静态列表会过期，也会变成背书。

### 采集来源与校验

S2 必须记录：来源 URL、版本号、哈希（有则校验，无则标注「未取得校验依据」）、下载时间、安装结果。禁止从第三方转载站、绿色版、破解版下载。

## 声明纪律

**每条能力声明后必须紧跟一句「它不覆盖什么」，且必须指向用户真正会推错的那一步。** 不接受「本产品不承担任何责任」这类空话。

| 声明 | 必须补的半句 |
|---|---|
| 未发现异常 | 未发现 ≠ 通过；未测量 ≠ 通过 |
| 本地化检测 | 免 Key 查询仍会向情报源暴露待查 IP；本地指采集与报告处理，不代表离线 |
| IPv6 已禁用 | 仅对指定环境生效，不影响其他出口 |
| IP 信誉读数良好 | 是数据源此刻的历史记录，不构成 上游服务商 的判断 |
| 配置完成 | 已改动，未验证——需要新的测量读数 |
| 报告全绿 | 只表示本工具测的项一致；服务端风控是黑箱，不保证账号状态 |
| 读数与出口一致 | 不代表匿名，也不代表账号会被接受 |

同一条纪律适用于 Agent 的每一句输出，不限于文档。

## 中立性承诺

本项目不含推广链接、返佣、付费推荐或赞助内容，不销售 VPS、代理、指纹浏览器或任何服务。任何形式的商业合作都不进入 SKILL.md、报告与读数。

## 变更规则

- 新增能力：先补本文件的阶段 / 状态 / 声明三处，再写代码。
- 新增外部请求：必须在声明纪律表中登记它暴露了什么。
- 与本文冲突的实现视为缺陷，不视为设计选择。
