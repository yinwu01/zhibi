# 完整能力范围与实现顺序

2026-10-19。当前发布为 v0.2.0a3，GitHub private；六组可选浏览器深入检查已接入，完整覆盖仍在推进。

**项目提供完整能力，用户按需启用。** 基础流程继续简单；额外检查、数据源、实验性对照与环境管理都进入可选模块范围，不能以“不默认执行”为理由删除。

## 验收基线

[能力覆盖清单](../architecture/capability-coverage.md)逐项列出已审查上游的能力、当前覆盖与依赖，后续每发现一个新项目继续补充。
只有实际可运行、能进入统一报告并完成相应验证的功能才算接入。宣传中的功能数量、计划中的模块和外链都不等于实现。

## 当前具备

- 自带 Python 核心的 Skill，检测和协助两种模式；默认离线，显式启用免 Key 信誉组合。
- IPv4/IPv6、高级浏览器导入、WebRTC、dig/ECS 观察、代理环境摘要。
- IPWhois、ProxyCheck、IPQuery、StopForumSpam 免费查询；IPQS、AbuseIPDB、ipapi.is 可选 Key 适配。
- 语言/时区/locale/UA 等部分浏览器采集；来源冲突、证据 Graph、报告、扫描对比与 IPv6 配置确认。
- 准备清单、异常分流、学习材料与教程模板。

MacOS + Codex 的 GitHub 下载、安装发现、无 Key 查询和报告生成已验收；具体范围见[首次使用实测](../archive/onboarding-validation.md)。

## 第一组：补齐只读检测与情报

- N03/N05/N07：指定代理/网卡、浏览器真实 DNS 与分流、产品端点诊断。
- F02/F03/F04/F06 已接入可选探针；F05/F07/F08 已有运行标记、浏览器逻辑 CPU 和本页权限观察，完整容器识别与系统交叉核对待补齐。
- I08–I15：逐个接入额外 IP 数据源、授权本地数据库、黑名单和明确选择的聚合服务。
- F10/F11、N08–N10：可选上游模型对照、扩展浏览器特征、其他服务/SMTP/TLS 观测。

按来源和模块分别提交，避免一个大开关隐含所有网络请求。Key 与费用的实际要求在接入时逐项验证，不预先宣称全部免费。

## 第二组：可选环境维护与交付

- E01/E02：实际浏览器集成、专用环境配置、切换和恢复。
- E03/E04：缓存清理、本地身份归档/切换/恢复；保留范围和备份验证。
- E05/E06：系统设置适配，目标客户端 安装方式、版本、修复与重装。
- E07/E08：网络配置交付、TUN/系统代理/SOCKS 链路检查与恢复。

提供固定版本适配器或独立实现，按平台逐项验收。基础检测不强制安装这些组件；用户选用时有可执行流程、成本说明、恢复和实际生效检查。

## 持续完善体验与分发

- N02/D03：用户选择环境与检测模块，浏览器测量回到同一份报告，减少手工搬运 JSON。
- I16/D06：上次问题 → 本次结果 → 剩余事项；现有 `scan-compare` 和 IPv6 确认接入直观流程。
- D02/D04/D05：脱敏分享、跨平台/宿主实机、自部署、插件分发、更新恢复和报告本地化。

这些工作改善使用方式，不替代前两组的能力补齐。所有未交付项保留在覆盖清单。

## 研究和教程

作者序言保持原文；三个 20x Max 账号的详细操作与观察窗口仍待作者提供。继续建设特征卡、来源版本、正常反例、事件 Graph 与自愿提供的案例。

检测特征可以全面；推断必须按证据强度解释。平台内部账户图、资格决定和封号概率不能通过拼接客户端特征冒充已测结果。

GitHub Actions 目前有账单/支出限额启动阻塞；Windows/Linux、目标客户端 宿主及 Key 来源现场验证分别保留为待验收，不影响对真实实现状态的记录。
