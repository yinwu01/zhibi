# 架构与实现状态

2026-10-19，当前发布 0.2.0a3。主要入口是内置检测核心的 Skill；独立核心和浏览器页面共用相同实现。

```text
用户的检测目标 / 准备流程
              ↓
   Skill：detect / assist
              ↓
  scripts/zhibi.py → 内置 zhibi-core.pyz
              ↓
  本地配置 / 浏览器导入 / 选定情报适配器
              ↓
  严格契约 → 来源、覆盖、时间与冲突 → 主动风控解释
              ↓
  私人快照 + 本地报告 + 证据 Graph + Agent 摘要
```

## 交付方式

- `scripts/build_skill.py` 生成完整 Skill ZIP 和标准库 Python zipapp；Python 3.9+，无运行时 pip 依赖。
- `scripts/install_skill.py` 安装到明确的宿主或目标目录，不覆盖已有 Skill。
- `scripts/verify_skill.py` 在仓库外解压并用隔离解释器验证发布物，不依赖源码路径。
- `start.html` 保留无 Python 的基础自检；高级浏览器页面由 `browser --advanced` 导出为单文件。

## 可选能力的目标结构

[能力覆盖清单](capability-coverage.md)是项目范围基线；下方模块表只描述当前实现。最终由同一个 Skill 调度可选模块：只读检测、外部情报、上游模型对照、环境维护与交付。每项声明依赖、平台、数据流、费用条件和验证方式。

默认检查无需全装依赖；用户选择额外模块时再准备其运行条件。系统变更和身份归档属于协助模式，可选且单独界定操作范围。没有安装的组件、未配置的服务、未开发的模块、执行失败与观测到问题分别报告。

这不是新增了一个可运行插件框架；统一模块选择/分发仍是待实现能力。现有扫描命令按当前支持的选项工作。

## 主动风控不是一个总分

每个增强发现包含层级、平台动机、测量依据、正常反例和下一步。
平台动机是研究语境；第三方标签只表示对应来源的观测或推断。

Graph 的节点是动机、公开来源、来源依赖、观测、解释和行动。
`shared_data_dependency` 显示已知上游依赖，未声明的来源不默认独立。
没有账号登录数据、真实平台账户关联图或对不可见特征的猜测补全。

`scan-compare` 需用户声明同一上下文；核心在本地比对 IP 和场景。
对象变化、测量变化和查询覆盖变化分开，不把评分变化当作因果或防封效果。

## 检测与外部边界

- 出口测量通过明确的 ipify IPv4/IPv6 端点。一次测量只描述到该端点的请求。
- 浏览器与 Agent 比较要求同端点、同地址族、相近时间；陈旧或自动化浏览器结果不能代替真实用户。
- WebRTC 收集用户选择的 Google STUN ICE 候选，不访问音视频设备；与同地址族 HTTPS 比较，空结果保留未知。
- IPWhois、ipapi.is、IPQS、AbuseIPDB 分别返回归属、网络标签、欺诈分和滥用记录。缺 Key 与套餐缺字段是显式状态。
- 每个来源每个目标最多一次请求，无重试、无重定向。IPv6 模式最多两个地址；底层 socket 超时 8 秒，系统 DNS 解析时间由操作系统控制。
- 当前检测核心不自动改变代理、系统设置、浏览器身份或账号状态；相应可选维护模块列入覆盖清单，交付后由协助模式按用户选择执行。

密钥仅保存在本机文件或明确命名的环境变量中，通过 Header/POST 发给对应服务。
报告无密钥，Agent 摘要不含原始 IP、浏览器 UA、供应商组织自由文本或原始响应。
完整快照私下保存；浏览器导出文件仅通过脚本读取。

## 版本与真实性

基础报告保持 0.1 契约；增强报告使用 `zhibi-scan-1`，浏览器探针支持版本 1 和 2。
来源解释由固定逻辑重新计算，导入报告中的自定义结论不能进入 Agent 摘要。
三个 `scan-demo` 场景始终标记合成；真实请求验证另行记录。

DNS 解析器观察已接入；其范围仅为 dig 默认查询链路，不代替浏览器 DoH 或系统分域解析。
付费密钥的现场验证、宿主自动发现与其他操作系统实机验收仍须单独记录。
当前没有 GitHub remote 或公开发布，详见 [验收记录](validation.md) 与 [交付清单](delivery-checklist.md)。
