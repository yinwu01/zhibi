# 假设、反驳与实验

理论需要给出会改变我们看法的证据。没有反驳条件的“环境越纯净越安全”不能成为工程规则。

## 研究问题

| 编号 | 假设与范围 | 验证方式 | 不足以支持它的证据 |
| --- | --- | --- | --- |
| H1 | 分开产品、阶段和结果，有助于准确分流用户问题 | 对自愿提供且脱敏的既有错误案例盲标，比较统一“风控”标签与阶段分类的一致性、误分率 | 单个 HTTP 403；无官方结果的猜测 |
| H2 | 明示未知与正常反例，能减少无依据配置修改 | 任务可用性实验；记录正确下一步、完成时间、无必要改动和理解程度 | 用户表示“看起来专业” |
| H3 | 证据图能降低政策更新后的遗漏 | 人工构造来源变更任务，测量受影响规则检索的完整性与维护耗时 | 图有很多节点 |
| H4 | 可比条件约束能减少出口差异误报 | 用有意分流、时间错位、地址族差异、测量失败的可复现场景验证 | 两个检测网站显示不同结果 |
| H5 | 个体历史可能提高异常解释能力 | 先在用户授权的既有事件记录中检验增量价值，比较单次快照；明确混杂与失访 | 仅凭 IP 变化推断跨账号关系 |

H4 的软件行为已有合成测试，真实用户可用性仍需验证。H1/H2/H3/H5 不是已验证效果声明。

## 案例最少要记录什么

入口、阶段、粗粒度时间、错误类别、已做动作、官方结果、观察截止时间、哪些字段缺失。
无需邮箱、Cookie、密码、手机号、完整 IP 或证件。作者于 2026 年 10 月 18 日自述已开通并稳定使用三个 20x Max 账号；
每次的注册时间、具体过程、稳定使用时长与逐账号观察记录仍留待作者补充。

样本必须包括正常使用、失败、未完成和失访。招募渠道可能造成选择偏差；
教程、代理服务和浏览器配置经常同时变化，不能把结果归因于其中一个变量。
同一帖子被多个列表转引仍是一条线索。

## 产品验收与效果研究分开

| 问题 | 当前可做的验证 |
| --- | --- |
| 是否测对 | 模拟超时、DNS/TLS 故障、响应格式、代理冲突、实际本地检查 |
| 是否解释对 | 正常反例、过期证据、错误产品语义、未知状态回归测试 |
| 是否能使用 | 新环境安装、真实生成报告、离线页面与移动布局、使用路径 |
| 是否改善账号结果 | 目前无结论；需要有分母、观察窗口、合法样本和混杂说明的研究 |

不通过批量注册、诱发违规或反复试探阈值制造标签。已有事件和自愿的正常使用记录足以启动方法研究。

## 主张更新流程

提议主张 → 登记原始来源及反例 → 明确适用范围 → 审查可观测性 → 必要测试 →
人工评审 → 更新状态和规则 → 生成目录并发布变更说明。

被反驳的主张保留历史并退出确定性判断，不删除不利案例。来源过期时先暂停确定解释，
不要用自动抓取结果或模型推测悄悄替换原依据。
