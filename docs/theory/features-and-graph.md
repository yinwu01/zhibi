# 特征、Graph 与时间

特征不以“深”或“表面”决定价值。需要看它对应哪个判断问题，平台是否可能观测，
我们是否能验证，以及它是否真的改变用户决策。

## 三层可观测性

| 层次 | 例子 | 可输出的结论 |
| --- | --- | --- |
| 本地直接观测 | 变量冲突、客户端存在性、固定端点响应 | 本次工具和上下文中的事实 |
| 代理观测 / 用户声明 | 第三方 ASN、真实地区、分流预期 | 带来源或声明标记的背景，不能代替平台数据 |
| 平台隐藏信息 | 跨账号图、内部信誉、训练标签、阈值 | 研究假设或未知，不填伪造分数 |

可计算组合应带上 `对象 + 端点 + 地址族 + 时间 + 观测方式`。
当前出口规则同时检查这些条件：五分钟内的同端点/同地址族样本，十五分钟内的实际浏览器上下文，
并排除已声明的自动化样本。用户声明有意分流时，相同读数可以产生不同建议。
时间窗口是项目的测量可比性约定，不是 目标服务 风控窗口。

## 两种图解决不同问题

**证据图已实现。** 来源、主张、特征和规则有稳定 ID、类型及有向边。
`zhibi theory --format json` 导出图；`zhibi explain` 返回具体规则的追溯信息。
来源带查阅时间/有效期，主张带范围、状态、反驳条件。图能回答“新证据影响哪些判断”，
但当前没有自动抓取、证据冲突裁决或图数据库。

**本地事件图已实现为用户提供快照的时间线。** 每项观测带对象与时间；
`timeline` 将运行与观测连接，只在用户明确声明相同上下文且输入背景一致时比较事实是否变化，
不输出原始 IP。时间线仍是私人材料。`compare` 则提供更小的报告状态比较。
没有跨账号历史推断，也不会自动发现或扫描历史目录。

```bash
zhibi timeline before/snapshot.private.json after/snapshot.private.json --out timeline.private.json
# 确认来自相同使用上下文时，再显式添加 --same-context
```

候选实体事件结构：

```text
一次使用事件 ──使用──> 浏览器或 CLI
       │                  │
       └─发生于时间──> 观测窗口
                          │
客户端 ──在特定端点观测到──> 出口
```

“同出口”是带时间的关系，不是“同一个人”的证明。企业 NAT、家庭网络、移动运营商共享出口
都是必须保留的正常反例。可视化更多节点不会消除观测缺失。

## 优先研究的特征

第一组服务于准备动作：产品/阶段、政策有效性、实际浏览器能力、客户端可用性、
代理变量冲突、端点可比性、地址族、错误所在层。

第二组服务于研究：事件频率与顺序、配置变化与错误出现的先后、共享依赖、
请求结果和账号结果的区别、行为协同性。先定义采集伦理与数据需求，再判断是否值得实现；
不自动读取会话、消息正文、支付关系或其他人的账号资料。

完整可观测性、反例及验证方法见 [特征目录](catalog.md)。
