# 从平台 motivation 到决策

用户问的是“我现在应该准备什么”。平台处理的可能是资格、盗号、支付、资源滥用、
内容政策或协同提取等不同问题。研究必须先写清目标，否则同一个 403 会被错误归为封号，
同一个正常差异会被误认为风险特征。

## 1. 先写损失，再找特征

| 研究目标 | 判断对象 / 事件 | 候选代价与动作 | 用户侧能验证什么 |
| --- | --- | --- | --- |
| 资格与政策范围 | 主体 / 注册申请 | 资格不符、错误拒绝；验证或拒绝 | 官方条件及真实使用背景，无法替平台核验 |
| 账号安全 | 会话 / 登录 | 盗用、误拦；额外验证或复核 | 明确的官方验证提示，部分本地环境变化 |
| 支付完整性 | 交易 / 订阅付款 | 欺诈、拒付、交易摩擦；验证或拒绝 | 官方付款结果；不采集支付凭证 |
| 资源与服务可用性 | 请求 / 使用 | 过载、不公平占用；限流或等待 | 用量提示、错误类别；不等于账号处分 |
| 内容与使用要求 | 请求 / 内容提交 | 不允许的使用、误拒；拒绝某次请求 | 官方提示类别；内容拒绝与账号限制分开 |
| 协同滥用与提取 | 跨账号行为 / 时间窗口 | 批量协同、知识提取；多层限制与复核 | 公开披露；平台全局关系通常不可见 |

表中是研究分类，不是对 上游服务商 实现的一一确认。

## 2. 一个用于提问的形式化模型

在业务事件 e、对象 u、时刻 t 上，平台拥有观测 x 和关系历史 G。
概念上，决策可以写成：

```text
选择行动 a，使下列期望代价较低：
E[业务损失(a, 隐藏状态) | x, G, e, t]
+ 正常用户摩擦(a) + 人工复核成本(a)
```

这只是决策论表达。知彼没有这些隐藏状态、真实损失函数、权重或阈值，也没有训练这个模型。
它的价值在于要求研究者回答：判错哪一类会付出什么代价？验证能否降低不确定性？
同一特征在注册和登录上为什么可能产生不同动作？

## 3. 公开资料提供了哪些支点

10 月的材料进一步介绍反蒸馏防护。这支持在其公开场景研究行为、关系和分层措施，
不构成普通用户注册阈值表。[2 月原文](https://www.anthropic.com/news/detecting-and-preventing-distillation-attacks)、
[10 月原文](https://www.anthropic.com/research/distillation-defenses)

Stripe Radar 将交易评估和允许、阻止、验证、人工复核等动作联系起来；其目标是支付交易。

## 4. 把模型翻译成用户行动

一个建议应当交代：`目标问题 → 当前观测 → 替代解释 → 动作 → 完成标准`。

例如浏览器与 CLI 出口不同：

- 目标：解释两个入口为何表现不同。
- 观测：同一端点、地址族、短时间内的出口不同。
- 替代解释：有意分流、负载均衡、代理范围不同。
- 动作：先核对用户预期，确属配置故障时才修改。
- 完成标准：复测结果符合预期；账号结果仍需独立记录。

“改成相同出口后注册成功”还存在时间、重试、验证完成等混杂因素，不能据此证明因果。
