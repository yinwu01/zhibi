# README 与首次使用设计

2026-10-18：根据用户反馈重做入口。上一版让读者先理解研究框架、安装 Python 和学习命令，
未能直接说明产品用途，也没有让基础检查开箱即用。

## 首页必须回答的问题

- 这是什么：从主动风控视角组织的 环境准备工具箱，包含本地检测、Skill 与 Tutorial。
- 给谁用：准备注册或开始使用 目标服务 的人。
- 有什么用：以本地 IP 与风险检测、Agent 自检、教程三个交付帮助注册准备；在每项旁边说明实际完成范围。
- 怎么开始：下载 start.html，打开，点击“开始检查”。

README 开头说明用途，保留直达快速开始的链接。
先放作者第一人称“写在前面”，保留实际使用动机、对不透明采集与零散推断的不满、从业视角和个人实践。
再按“官方资料与社群反馈 → 三种具体交付”展开，
每项写清用途、原理、入口和当前状态；之后提供基础版操作步骤与真实界面。
六层框架放在交付之后，完整风险/特征/交付矩阵进入独立文档。
不把命令数量、图谱术语、研究条目数量当成用户价值。

## 动机要有明确的主张

从检测结果与零散分析难以形成行动依据的困境切入。保留四个动机：
不交出 Cookie、从平台风控视角研究、三个账号的个人实践、质疑缺乏依据的检测结论。
以主动风控视角连接它们，说明不同场景、风险问题和可观测性如何组织研究。
本地检测、Skill、Tutorial 各自对应具体用户问题，并明确安装条件与当前状态。

Skill 用一张表说明检测与协助两种模式。前者调用检查，后者按用户流程推进并按需使用前者。
成熟能力优先复用，但候选审查、代码接入与宿主实测分别标注；作者流程未提供时不虚构步骤。

“看清 IP 风险，让 Agent 自检，知道注册前该做什么”是主线。
第一项交付必须升级到有来源与时效的 IP 情报；没有完成前明确标注增强版待实现。
不能把高级服务名称列出来就宣称已经达到其能力，也不能只增加命令数量。

作者提供的序言沿用原文。仅允许调整语序、段落和 Markdown 格式；不得自行改写措辞、立场、论点或添加解释性声明。
技术能力和当前实现状态在后续产品章节单独据实维护。

## 产品入口与说明一致

根目录 start.html 不需要 Python、终端、安装依赖或已有 目标账号。
打开后默认不联网。检查结果和下一步直接显示在页面，保存文本即可留档。
IP 查询可选；高级 JSON 导出收进折叠区。

该页面只做浏览器基础自检。系统代理、IPv6、完整规则报告等能力仍通过
Skill / Python 核心使用，首页明确区分范围。
