# 项目闭环进度（2026-11-05）

目标：先扫描本机与用户 VPS，按需配置服务器进程的网络运行环境，提供浏览器可使用的连接，实际复测后交付。

本轮完成：修复 flow 对真实浏览器导出结构的读取；拒绝陈旧/自动化观测；复用同族 HTTPS/STUN 比较，不把空候选当通过；deliver 调用两端验收并保留浏览器结果到 JSON/HTML。

仍须完成（不得据当前单元测试宣称整体就绪）：
- 主 Skill 改为扫描优先、按需部署、可选浏览器；引导安装允许按实际环境选择适配方式。
- 分离交互进程、一次性命令、后台服务；提供真正可使用的网络路径、进程启动/连接/停止与健康验证。
- 通用 SOCKS5/HTTP 浏览器接入与现有 SSH 隧道贯通；具体浏览器按能力适配，不能宣称所有品牌均实测。
- 移除机房标签/公共 DNS 等无路径证据的风险判定。
- 阶段状态、原值备份、远端回滚、复现命令与交付接通。
- 覆盖集成测试、发布物隔离验证和实际 Linux/浏览器验收。真实部署目标需用户明确指定，不复用其他项目服务器。

测试环境：本机设置 HTTP_PROXY/HTTPS_PROXY，会干扰 loopback Host 拒绝测试；本地测试应排除这两个代理变量，不能据代理返回判定接收器行为。

第二轮：新增 connect，前台 SSH SOCKS5 与可选远端 shell/PTY 进程；加入命令私密文件、端口和退出状态测试。主 Skill 已改为扫描优先、按需配置、品牌中立，新增 runtime 参考。尚需真实隧道/进程集成验证，后台托管与恢复仍待完成。已向用户询问授权 VPS 与测试命令。

第三轮：systemd 部署备份现有 unit，拒绝别名/厂商 unit/drop-in，先验证后替换，启动失败尝试恢复；新增真实 shell + 模拟 systemctl 的部署/恢复测试。build 先落盘原值并在错误时保留部分结果；deliver --build-receipt 生成远端服务/时区恢复命令，缺回执时明确失败。仍需真实 systemd 与应用健康验收，locale 生效与评分修正仍未完成。

第四轮：出口组织标签改为背景，不再将机房判失败；DNS 配置不再冒充泄漏实测；systemd 存在不再算运行稳定；缺失时区/语言不算冲突。新增回归用例并扩展仓库外发布验证到 connect。部署回执校验完整 SSH 目标，验收服务名增加校验。

第五轮：connection-check 显式走本机 SOCKS5h 查询预期出口，不回退直连；connect 传递真实退出码。新增独立 Paramiko 回环 SSH 服务集成验证，真实 OpenSSH 的密钥认证、SOCKS HTTP 转发、远端命令和退出码均通过。测试不代表真实 Linux/systemd 或浏览器验收。Paramiko 仅为隔离测试依赖，核心运行依赖保持标准库。

第六轮：新增 connect --export-out 独立连接文件夹，含标准库 start.py、600 权限私人连接配置、通用 SOCKS5 参数、显式出口检查与停止说明；无 Agent/源码依赖，保留 SSH/远端退出码。独立解释器运行测试通过；README 已补使用入口与未验收边界。

第七轮：启动器/CLI 共用前台子进程生命周期处理，SIGTERM/SIGHUP/Ctrl-C 清理自身 SSH 子进程。真实协议集成测试已验证仅结束启动器后 SOCKS 端口关闭。交付补全 SSH 用户/端口/密钥复查参数，浏览器文档改为实际观测而非假定配置，旧远端/交付参考与新主线同步。

第八轮：真实桌面 Chrome 的独立 headless 配置经 SOCKS5/SSH 加载仅测试端可解析的域名页面，通过 DOM 与服务端目的地址双重核验；未使用用户浏览器配置。新增 CI 集成步骤但未推送。当前完整验收矩阵见 acceptance-matrix.md。
