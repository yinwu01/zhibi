## 采集主机真实调用

使用完整只读组合执行，不带 Key。IPWhois、ProxyCheck、IPQuery、StopForumSpam、IP2Location.io、DB-IP 取得实际响应；匿名 ipapi.is 仅返回部分归属。缺 Key 的接口在发请求前跳过。

公共 HTTP 端点、SMTP 六个 TCP 组合、采集主机 TLS、系统配置与 CLI 安装状态均运行；部分 HTTP 端点拒绝请求，只记录响应，不视为账号风控或地区解锁失败。

## AdsPower 验收

现有「目标服务 2」，AdsPower Global 8.9.23 / SunBrowser。保留原有会话和配置，单独打开本项目探针。

发现并修复的流程问题：该环境访问 127.0.0.1 一次性 HTTP 页返回 ERR_EMPTY_RESPONSE，终端同址返回 200；原因尚未确定。新增 `session --file` 路径：打开本地 HTML，测量后按命令给定路径保存 JSON，核心自动接续生成报告。不更改用户代理或关闭浏览器保护。

完整实测已完成：实际浏览器 v4 导出通过严格校验，核心以 `target=browser` 查询该次 IPv4 并生成报告。第一轮由 Agent 将已下载的指定导出复制到会话目录，后续查询和生成自动完成。

| 实测项 | 实际结果 | 范围 |
| --- | --- | --- |
| 浏览器 IPv4、免 Key 信誉 | 已取得；已查标签与评分未提示需要处理的问题 | 当前浏览器所测 IP |
| StopForumSpam、Spamhaus/SpamCop、IPsum/DROP | 本次未命中 | 各库当前可用记录，非全网保证 |
| 六项本地详情、Canvas/WebGL/Audio | 均取得读数；Canvas 两次一致 | 浏览器可观测值，不证明物理设备真伪 |
| IPv6 | 请求未成功，关闭配置尚未核实 | 保留专用环境关闭建议，不判已关闭 |
| WebRTC | 超时，0 个候选 | 无可比出口，不判没有泄漏 |
| 浏览器 TLS | 外部观测未取得读数 | 采集主机 TLS 成功不能代替它 |
| 浏览器 DNS | 未配置自己的观测端 | 模块给具体部署/配置步骤 |
| CheckCC 研究对照 | 两套模型已运行 | 不影响 IP 信誉或账号资格结论 |
| 有 Key / MMDB / 显式路由 / 预期 IP | 没有对应配置 | 可选项保持未配置，不伪造分数 |

`session --file` 另增加了默认 Downloads 内本次随机文件名的自动接收，且只读取这一文件；部分写入与其他导出不会触发。接收逻辑通过夹具测试；随后在同一「目标服务 2」用最终探针重新测量并点击保存，核心自动接收随机命名的下载文件、完成全量查询和报告生成，无手工 JSON 复制。
