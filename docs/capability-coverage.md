# 可选能力目录与验收状态

2026-10-20 产品收敛：主流程为“选择实际环境 → 主动检查 → 协助配置 → 复查交付”。默认只执行对应的基础检查，已有能力保留为 optional。这份清单用于查阅来源、依赖和验收边界，不再驱动每轮扩功能，也不是新用户待办。

以下能力状态沿用 v0.3.0a2 的实现边界；v0.3.0a3 只整理主流程与报告，不把“部分实现”变成“已完成”。研究过源码、链接到上游或提供手工教程，都不能算已经实现。

## 覆盖规则

1. 需要比较某项上游能力时记录：来源/固定版本、可观测内容或操作、当前覆盖、实现方式、依赖和验收条件。
2. 默认流程围绕当前用户任务，已有工具集按需启用；本轮停止横向扩功能。依赖、Key、费用与未验收边界继续保留。
3. 采集能力和风险解释分开：可以检测语言、时区、字体、Emoji；不能仅因检测到某属性就宣布会封号。上游评分可做可选研究对照，标明原模型和适用范围。
4. 复用方式可以是保留许可的代码适配、独立实现，或固定版本的外部工具适配器。适配器必须真的能运行、导入结果并生成统一报告；只有链接不算接入。
5. 不复制所有默认行为。报告分享改为用户选择、先预览脱敏；系统修改和本地身份操作放在协助模式，按用户选择执行，保留恢复与复验。
6. 任一计划项只有交付脚本/可调用适配器、安装与可选依赖说明、结果解释和行为验证后，才可改为已实现。

## 可选模块的产品契约

每个模块最终需要声明：ID、当前状态、入口、支持平台、依赖、Key/费用、接收方与数据、读写范围、输出字段、失败处理、复查条件和测试证据。

用户只会看到：

- **基础检查**：当前的免 Key 流程，得到简单报告。
- **可选检查**：用户选择更深入的网络、浏览器、IP 数据源和服务诊断；依赖缺失时说明如何配置。
- **协助操作**：用户选择环境维护/配置/交付，按具体范围执行并复验。

v0.3.0a2 已提供 `modules`、`suite --preset all` 和实际浏览器 `session`。全量指已接入的只读模块，并不表示本表所有部分项已完成。维护动作不会由全量检测触发。

本轮细节与实测边界：[可选工具](../tutorials/optional-modules.md)、[环境维护](../tutorials/environment-maintenance.md)、[验收记录](full-coverage-validation.md)。

`未选择`、`未配置`、`暂不支持该平台`、`尚未实现`、`执行失败`和`检查发现问题`必须区别显示。用户未选模块不算失败；用户选择的未实现模块必须明确承认缺口，不能说“没有必要，所以不测”。

“全量检测”表示启用已选择且可用的只读检测集合，不自动注册服务、购买资源、改变系统或上传私人报告。仅选择了某个付费提供商也不授权自动付费。

## 关闭一个覆盖缺口的标准

- 有真实可运行入口及固定依赖，来源/许可记录齐全；用户不需要复制粘贴上游脚本才能实现。
- 无 Key、无额外软件或平台不支持时清楚告知，基础流程仍可用；不伪造 0 或通过。
- 输出进入统一报告和最小 Agent 摘要；私人数据保留在本机。
- 有正常、失败、缺字段等必要验证，标明实机/真实服务验证范围。
- 涉及修改时有具体变更、恢复方式和生效复验；涉及研究分数时能追溯模型版本和输入。
