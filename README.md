# 知彼 · 让 Agent 帮你准备好网络环境

**从风控的视角来做好网络环境切换的准备**

知彼是一个自带本地检测脚本的 Skill以及系列脚本。搭配具备 **computer use（操作浏览器和桌面）** 能力的 Agent，它能在你实际使用的环境里完成检查、打开相关设置、协助处理发现的问题，再复查结果。

你说清楚要检查哪个环境，Agent 负责推进：**选择环境 → 主动检查 → 协助配置 → 复查交付。** 默认免 Key；已有深入检测按需开启。

出口和浏览器不用先备齐：没有指纹浏览器时，Agent 按判据列出候选、由你选，再下载安装并配好出口与系统设置；已有则直接从配置开始。缺哪一件、由谁来做、能不能补，它会先说清楚——不推荐、不返佣、不卖任何服务。

## 我想要写在前面的

换一个网络环境去用一个服务，对很多人来说一直是件麻烦事。换机器、换线路、换浏览器配置之后，往往会出现一堆说不清的问题：页面能打开但登录被拒；同一个账号在家里好好的，到了服务器上就不行；代理明明开了，某些流量还是从本地出去。于是各种「检测网站」应运而生，打着给你检测的口号，实质不知道拿你的数据去做了什么；坊间也流传出很多离谱的说法，比如「输入中文会导致封号」「换个时区就会被标记」。

我在 ByteDance 某面向国际应用的风控团队学习过几个月，也长期稳定地用过多个付费账号。这段经历让我意识到一件事：**风控看的从来不是单个信号，而是这个环境是否自洽。** 时区、语言、DNS 出口、IP 类型、浏览器指纹——单独看几乎没有判别力，彼此矛盾才构成可疑。所以「输入中文就封号」这类传闻基本是扯淡；而「代理开着但 WebRTC 从本地出去」这种自相矛盾，才是真的会被注意到。

于是这个项目的出发点变得很清楚：**不是教你怎么伪装成别人，而是从风控的视角，检查你自己的网络环境是否自洽、切换是否干净。** 你的语言、时区、出口、浏览器本来就该对得上；如果对不上，问题通常出在配置上，而不是出在你的身份上。在切换环境之前把这件事查清楚，是任何场景都该做的一步。

故有了本项目：知彼，所谓知己知彼，百战不殆。

本项目主要包含三部分：
1. **本地化的环境检测**：测量、判读和报告都在你自己的机器上完成，不经过第三方检测站，也不上传 Cookie 与登录凭据。边界要说清楚：免 Key 的情报查询仍会让对应服务看到待查 IP；「本地」指采集与报告处理，不代表完全离线（[数据流说明](docs/reference/privacy.md)）。
2. **环境判读 Skill**：不替你做决定，也不推荐任何服务商。它测量你的实际环境，把每一项发现分成技术问题、渠道问题、合规问题三类——技术问题能修，渠道问题要换路，合规问题没有技术解。
3. **稳定使用实操 Tutorial**：基于我本人稳定持有 3 个账号的使用经验整理出的实操教程。对于很多人来说，可能这部分才是更关键的；其余的检测流程直接交给 Agent 即可自动完成。

这就是为什么我们要做这件事。

## 快速开始

需要 **Python 3.9+** 和一个本机 Agent；推荐能操作你的实际浏览器与桌面的宿主。仅安装 Skill 不会给宿主增加 computer use 能力；没有这项能力时，Agent 仍可运行检测，少量界面操作需要你接手。

1. 下载完整 Skill ZIP（`Releases` 页面的 `zhibi-skill.zip`），解压。
2. 把整个 `zhibi` 文件夹放到对应目录；保留 `assets`、`scripts`、`references`。已有旧版先移出备份。
3. 新开 Agent 会话，调用知彼，告诉它你的实际使用环境。

| 宿主 | 安装位置 | 调用 |
| --- | --- | --- |
| Codex 桌面端（推荐，具备 computer use） | `~/.agents/skills/zhibi/` | `$zhibi` |
| 其他 Agent 宿主 | 由 `scripts/install_skill.py --dest` 指定 | 按宿主方式调用 Skill |

例如：

> 用知彼检查我准备用的 AdsPower「工作环境 2」。允许使用默认免 Key 查询。你来操作浏览器完成检查，核对相关设置；发现问题后说明具体修改，按我授权的范围处理并复查，最后打开报告。

**不需要 pip，不需要先注册 IP 情报服务，不需要手工复制检测 JSON。** Agent 会打开探针、执行检查、保存到本机并生成报告。若宿主无法操作该浏览器，它会交代唯一需要你完成的界面步骤。

> 当前仓库为 private，下载需要获邀的 GitHub 账号。Windows 将 `~` 替换为用户目录，命令使用 `py -3`。

## 实际会得到什么

一份保存在本机的报告，以及 Agent 对下一步的明确说明。首页只展示当前任务需要的检查；技术读数和可选模块折叠收纳。

下面是**示意**，不是你的实测结果：

> **IP 已查项未发现需处理的问题；还需核对专用环境的 IPv6 配置。**
> 下一步由 Agent 打开对应设置检查。确认有作用于该环境的禁用配置后，重新测量并记录依据。

| 检查项 | 结果 | 建议 |
| --- | --- | --- |
| 实际浏览器出口 | 通过 | 本次已取得，可继续查询 |
| IP 标签与历史记录 | 已查项未命中 | 保留当前配置 |
| 专用环境 IPv6 | 待核对配置 | Agent 检查生效设置，再复查 |

“请求超时”和“没有配置额外 Key”不会被包装成风险分；也不会为了让表格全绿就改你的设置。报告描述本次观测，不保证 目标服务 的账号处置结果。

## 自动化到哪一步

同一个 Skill 保留两个模式，Agent 根据你的请求选择：

| 模式 | Agent 实际做的事 | 交付 |
| --- | --- | --- |
| **检测**：“看下我的环境” | 找到实际浏览器，运行免 Key 检查，读取摘要、打开报告 | 发现了什么、是否需要处理、下一步 |
| **协助**：“帮我配置并检查” | 根据发现或你提供的教程打开设置，执行已授权的操作，保存修改前依据，同环境复查 | 做了什么、验证了什么、哪里仍需你接手 |

computer use 负责真实界面操作，本地脚本负责测量、查询和报告。已有 API 或本地工具能可靠完成的步骤直接调用，不强制逐个点击。

默认核对实际出口、可用 IP 标签与记录、专用环境 IPv6 策略。WebRTC 等深入检查按具体问题选择。定位到某项问题后才展开对应教程和工具，避免把整套功能清单交给用户。

涉及验证、付款、权限或超出既有授权的修改时，Agent 留下明确接手点。作者三个账号的详细流程仍待补充；目前提供的是环境检查与配置协助，不冒充已完成的注册教程。

## 为什么从主动风控角度做

每个建议都要说明：**想避免什么问题 → 本次观察到什么 → 证据支持到哪一步 → 做什么 → 如何复查。**

例如，浏览器和终端出口不同，首先意味着要在实际浏览器检测；单凭这个差异不要求用户换 IP。IPv6 请求失败意味着本次没连通，要确认关闭仍需检查配置。中文、时区、字体不会单独触发本项目的“风险判定”。

社区经验和公开政策帮助提出检查假设；它们需要来源、适用条件和可复现的验证。证据 Graph 留在研究与解释层，供追溯判断依据。

## 可选能力

已有能力全部保留。需要额外数据或遇到具体问题时，让 Agent 按需启用：

- **更多 IP 情报**：IPQS、AbuseIPDB、ipapi.is 等；[免费额度与 Key 配置](docs/archive/tutorials/providers.md)。
- **深入环境诊断**：WebRTC、DNS、浏览器属性与渲染、名单与连通性；[可选模块说明](docs/archive/tutorials/optional-modules.md)。
- **配置与维护**：支持的配置计划、恢复、归档和安装修复；[操作范围与复查](docs/archive/tutorials/environment-maintenance.md)。

[完整能力与状态](docs/architecture/capability-coverage.md)是查阅目录，不是新用户待办清单。全量模式仍可显式使用；其结果放在报告的可选检查中，不扩大主结论的范围。

<summary>源码安装、手动命令与无 Agent 入口</summary>

```bash
git clone https://github.com/yinwu01/zhibi.git
cd zhibi
python3 scripts/install_skill.py --host codex
```

其他宿主用 `--dest` 指向自己的 skills 目录。实际浏览器的默认检查：

```bash
python3 ~/.agents/skills/zhibi/scripts/zhibi.py session --preset basic --network
```

若指定环境不能访问回环地址，加 `--file`，在同一浏览器打开返回的本地文件。采集后自动接收本次文件并生成报告。
只检查终端：`scan --network --reputation --progress`。它不能代替实际浏览器的结果。
单文件 [start.html](start.html) 保留为手动基础入口；无需 Agent 或 Python。

## 数据与复用

报告在本机生成，Cookie、登录凭据和私人快照不上传聊天或检测网站。公网测量及 IP 情报查询仍会让对应服务看到请求 IP 或待查 IP；“本地”指采集与报告处理，不代表完全离线。[数据流说明](docs/reference/privacy.md)

适配了 CCBaga、CheckCC 的部分成熟检测代码，具体版本、许可和改动见[复用记录](docs/research/upstream-reuse.md)。项目自身的诊断与解释会保留证据边界，不把上游经验分数变成 账号处置概率。
