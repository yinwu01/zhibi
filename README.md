# 知彼 · 让 Agent 帮你准备好网络环境

**从风控的视角来做好网络环境切换的准备**

知彼是一个自带本地工具的 Agent Skill。它检查你的网络环境，协助你在 VPS 上运行指定程序，并把本地指纹浏览器接入同一条线路，再核对实际效果。

**你可以从本项目拿到两套配合使用的环境：**

- **服务器端的应用运行环境**：在你自己的 Linux VPS 上安装和运行应用，按需要配置时区、语言与进程托管，并检查实际网络出口。应用在服务器上执行，使用该服务器配置的网络路径。
- **本地的浏览器操作环境**：在你选择的指纹浏览器中创建或配置专用环境，通过 VPS 连接网络，并按目标区域核对时区、语言、DNS 与 WebRTC 等可观测项。账号登录和网页操作仍在你的本地浏览器中完成。

形象一点说，就是给应用和浏览器准备一套特定区域的使用环境，来一次 **“区域用户 cosplay”**：应用在 VPS 上运行，本地浏览器通过这条线路操作，再逐项核对环境读数。

Agent 负责推进：**扫描当前环境 → 确认配置需求 → 准备 VPS 并运行程序 → 配置浏览器 → 实际复测与交付。** 安装与配置方式根据你的现有环境安排。

## 在更小的环境里，做好一致性与信息暴露控制

**知彼的目标，是在更小、更专用的运行与操作环境中，实现环境信息的一致性，并尽可能减少无关信息的暴露。**

应用运行在专用 Linux VPS 上，本地操作通过独立指纹浏览器完成。我们围绕目标区域配置并核对网络出口、时区、语言和浏览器网络路径，同时减少无关组件、扩展、权限与历史配置的干扰，让整个环境更稳定、更简单、更容易验证。

1. **环境信息一致**：检查应用与浏览器的实际网络出口，核对选定的时区、语言和路由，处理意外直连与配置冲突，并在修改后重新测量。
2. **信息暴露更少**：用专用目录隔离浏览器历史与存储，按用途限制定位、摄像头、麦克风、通知、扩展与同步，让程序和浏览器只承担当前用途。

当前已实现服务器进程运行、浏览器代理接入、环境检测、独立连接交付及服务恢复；新增 `browser-workspace` 可为用户选择的 Chromium 浏览器创建独立配置，默认限制上述四项权限、关闭扩展与同步，并配置 SOCKS5 和 WebRTC UDP 策略。已有指纹浏览器则由 Agent 在其配置界面或受支持 API 中设置，并复测。

应用请求、账号历史与服务端记录由平台掌握；本项目控制和验证的是运行环境、浏览器设置及网络路径。具体实测状态见[验收矩阵](docs/implementation/acceptance-matrix.md)。

## 使用前必须准备什么

**使用上述完整流程，必须有一台你有权管理、能够通过 SSH 登录的 Linux VPS。** 只有机场订阅或共享代理节点，不能替代这台服务器。尚未准备 VPS 时，可以先运行本地检测。

- **出口可以是家宽／ISP 类型，也可以是机房类型**；VPS 是运行程序的服务器，出口类型是线路属性，两者需要分别核对。使用家宽出口时，还需要相应的线路或代理资源。
- **要求使用独享、来源清楚的出口，不使用被大量用户共用的机场节点。** 本项目围绕你可管理的服务器和线路配置，不把公共机场节点作为完整方案的基础。
- **独享不等于历史清白。** VPS 独享也不自动代表公网 IP 独享；当前分配方式与可查的历史记录需要分别检查，无法证明一个地址从未被别人使用过。

浏览器可以已有，也可以由 Agent 协助准备。支持 SOCKS5 的普通浏览器或指纹浏览器可以按协议接入；具体客户端仍需逐个配置和验证。不推荐、不返佣、不销售 VPS、线路或浏览器服务。

## 我想要写在前面的

换一个网络环境去用一个服务，对很多人来说一直是件麻烦事。换机器、换线路、换浏览器配置之后，往往会出现一堆说不清的问题：页面能打开但登录被拒；同一个账号在家里好好的，到了服务器上就不行；代理明明开了，某些流量还是从本地出去。于是各种「检测网站」应运而生，打着给你检测的口号，实质不知道拿你的数据去做了什么；坊间也流传出很多离谱的说法，比如「输入中文会导致封号」「换个时区就会被标记」。

我在 ByteDance 某面向国际应用的风控团队学习过几个月，也长期稳定地用过多个付费账号。这段经历让我意识到一件事：**风控看的从来不是单个信号，而是这个环境是否自洽。** 时区、语言、DNS 出口、IP 类型、浏览器指纹——单独看几乎没有判别力，彼此矛盾才构成可疑。所以「输入中文就封号」这类传闻基本是扯淡；而「代理开着但 WebRTC 从本地出去」这种自相矛盾，才是真的会被注意到。

于是这个项目的出发点变得很清楚：**不是教你怎么伪装成别人，而是从风控的视角，检查你自己的网络环境是否自洽、切换是否干净。** 你的语言、时区、出口、浏览器本来就该对得上；如果对不上，问题通常出在配置上，而不是出在你的身份上。在切换环境之前把这件事查清楚，是任何场景都该做的一步。

故有了本项目：知彼，所谓知己知彼，百战不殆。

本项目主要包含三部分：
1. **本地化的环境检测**：测量、判读和报告都在你自己的机器上完成，不经过第三方检测站，也不上传 Cookie 与登录凭据。边界要说清楚：免 Key 的情报查询仍会让对应服务看到待查 IP；「本地」指采集与报告处理，不代表完全离线（[数据流说明](docs/reference/privacy.md)）。
2. **环境判读 Skill**：不替你做决定，也不推荐任何服务商。它测量你的实际环境，把每一项发现分成技术问题、渠道问题、合规问题三类——技术问题能修，渠道问题要换路，合规问题没有技术解。
3. **稳定使用实操 Tutorial**：基于我本人稳定持有 3 个账号的使用经验整理出的实操教程。对于很多人来说，可能这部分才是更关键的；其余的检测流程直接交给 Agent 即可自动完成。

这就是为什么我们要做这件事。

## 快速开始

完整配置需要上述 **Linux VPS**、本机 **Python 3.9+**、**SSH 客户端**和一个本机 Agent；推荐能操作你的实际浏览器与桌面的宿主。仅安装 Skill 不会给宿主增加 computer use 能力；没有这项能力时，Agent 仍可运行检测，少量界面操作需要你接手。

当前公开源码可直接安装，让 Agent 执行：

```bash
git clone https://github.com/yinwu01/zhibi.git
cd zhibi
python3 scripts/install_skill.py --host codex
```

安装器会构建完整 Skill，包括脚本、参考资料与内置核心；已有安装不会覆盖。其他宿主用 `--dest /path/to/skills/zhibi` 指定目录。安装完成后，新开 Agent 会话调用知彼。

发布包上线后，也可以下载 `Releases` 页面的 `zhibi-skill.zip`，将完整 `zhibi` 文件夹解压到下面的安装位置。不要只复制 SKILL.md。

| 宿主 | 安装位置 | 调用 |
| --- | --- | --- |
| Codex 桌面端（推荐，具备 computer use） | `~/.agents/skills/zhibi/` | `$zhibi` |
| 其他 Agent 宿主 | 由 `scripts/install_skill.py --dest` 指定 | 按宿主方式调用 Skill |

例如：

> 用知彼检查我准备用的 AdsPower「工作环境 2」。允许使用默认免 Key 查询。你来操作浏览器完成检查，核对相关设置；发现问题后说明具体修改，按我授权的范围处理并复查，最后打开报告。

**不需要 pip，不需要先注册 IP 情报服务，不需要手工复制检测 JSON。** Agent 会打开探针、执行检查、保存到本机并生成报告。若宿主无法操作该浏览器，它会交代唯一需要你完成的界面步骤。

Windows 将 `~` 替换为用户目录，Python 命令使用 `py -3`。

## 实际会得到什么

仅检测时，你会拿到本地报告与下一步建议。继续配置时，还会拿到服务器进程的运行方式、本地浏览器连接入口，以及启动、停止和恢复说明。报告首页只展示当前任务需要的检查；技术读数和可选模块折叠收纳。

下面是**示意**，不是你的实测结果：

> **IP 已查项未发现需处理的问题；还需核对专用环境的 IPv6 配置。**
> 下一步由 Agent 打开对应设置检查。确认有作用于该环境的禁用配置后，重新测量并记录依据。

| 检查项 | 结果 | 建议 |
| --- | --- | --- |
| 实际浏览器出口 | 通过 | 本次已取得，可继续查询 |
| IP 标签与历史记录 | 已查项未命中 | 保留当前配置 |
| 专用环境 IPv6 | 待核对配置 | Agent 检查生效设置，再复查 |

“请求超时”和“没有配置额外 Key”不会被包装成风险分；也不会为了让表格全绿就改你的设置。报告描述本次观测，不保证 目标服务 的账号处置结果。

## 自动化到哪一步

同一个 Skill 保留两个模式，Agent 根据你的请求选择：

| 模式 | Agent 实际做的事 | 交付 |
| --- | --- | --- |
| **检测**：“看下我的环境” | 找到实际浏览器，运行免 Key 检查，读取摘要、打开报告 | 发现了什么、是否需要处理、下一步 |
| **协助**：“帮我配置并检查” | 根据发现或你提供的教程打开设置，执行已授权的操作，保存修改前依据，同环境复查 | 做了什么、验证了什么、哪里仍需你接手 |

computer use 负责真实界面操作，本地脚本负责测量、查询和报告。已有 API 或本地工具能可靠完成的步骤直接调用，不强制逐个点击。

默认核对实际出口、可用 IP 标签与记录、专用环境 IPv6 策略。WebRTC 等深入检查按具体问题选择。定位到某项问题后才展开对应教程和工具，避免把整套功能清单交给用户。

涉及验证、付款、权限或超出既有授权的修改时，Agent 留下明确接手点。作者三个账号的详细流程仍待补充；目前提供的是环境检查与配置协助，不冒充已完成的注册教程。

## 检查之后直接使用

当前开发版增加了 VPS 进程与本地浏览器的连接入口。你可以只检查，也可以让 Agent 继续准备运行环境。浏览器品牌由你选择，支持 SOCKS5 的普通浏览器和指纹浏览器均可按相同协议接入，具体品牌需要逐个验证。

主流程：**扫描当前环境 → 询问是否配置 → 准备 VPS 并运行命令 → 配置所选浏览器 → 实际复测与交付。**

- **交互式程序或一次性命令**：`connect` 通过 SSH 执行用户提供的私人脚本，可分配终端，同时提供本机 SOCKS5。
- **后台服务**：`build` 用 systemd 托管适合后台运行的程序，保存部署原值和服务恢复回执。已有服务替换前备份，启动失败时尝试恢复。
- **后续自己使用**：`connect --export-out` 生成独立启动文件夹，包含 `start.py`、通用浏览器代理参数与使用说明。需要本机 Python、SSH 和原密钥；不依赖继续打开 Agent 会话。
- **验证**：`connection-check` 检查指定代理的出口；`session` 测实际浏览器；`accept` 和 `deliver` 保留两端结果。应用的实际操作仍须成功，才能宣布可用。

命令示例（由 Agent 补齐本次参数并执行）：

```bash
# 仅导出，不连接；该目录包含私人连接信息
zhibi connect --host HOST --user USER --identity KEY --export-out ./my-connection
# 运行连接并同时启动远端程序；脚本文件权限须为 600
zhibi connect --host HOST --user USER --identity KEY --command-file ./start.private.sh --interactive --apply
# 在连接运行时验证本机 SOCKS 的出口；不回退直连
zhibi connection-check --local-port 10818 --expected-ip EXPECTED_IP --network
```

SSH SOCKS 是 TCP 通道，不提供 UDP 转发，DNS 与 WebRTC 要按浏览器能力另行配置并实测。远端进程使用服务器现有路由；本地浏览器与远端进程共用出口，不意味着它们是同一设备。交互连接断开不保证远端进程继续运行；需要持续托管时选择适合的后台模式。

### 用普通命令进入专用进程环境

在 Linux VPS 上，`process-workspace` 创建 bwrap 工作区，`process-entry` 为应用生成独立命令入口。入口与应用安装目录分开：更新应用文件后，再次运行相同命令仍经过工作区启动器。

```bash
# WORK 与 APP_DIR 是已存在的绝对目录；PROFILE 是新的绝对目录
zhibi process-workspace --workdir WORK --app-dir APP_DIR --out PROFILE \
  --timezone America/Los_Angeles --locale C.UTF-8
# APP_DIR 在沙箱中只读映射为 /opt/app；按实际安装结构填写程序路径
zhibi process-entry --workspace PROFILE --name myapp --program /opt/app/bin/myapp
```

执行输出中的 `activate` 命令，将专用入口放在当前 shell 的 PATH 前面；用 `type -a myapp` 排查同名别名或函数，用 `command -v myapp` 确认指向生成的入口。需要长期使用时，将该 PATH 设置写入对应 shell 配置。启动器缺失或 bwrap 不可用时直接失败。应用更新在宿主侧进行，工作区内应用目录保持只读。

默认网络模式 `isolated` 没有外部连接；显式 `--network host` 使用服务器现有网络；`--network proxy` 在无外部路由的网络空间内，通过私人 Unix SOCKS5 socket 与固定 SHA256 的 graftcp 联网。`proxy-gateway` 可在服务器启动该私人端点。TCP、DNS、子进程、IPv4/IPv6 直接 UDP 阻断和代理停止后的失败行为已在 Linux 隔离测试中验证；项目网关的真实 HTTPS 请求也已通过。持续托管与完整应用交付仍需验收。详细参数见 [进程包裹](docs/implementation/process-wrapper.md)。

需要持续运行时，`runtime-service --workspace PROFILE --name zhibi-NAME --out SERVICE_DIR` 生成用户级 systemd 网关服务及独立的安装、状态、恢复命令。可在末尾追加 `-- PROGRAM ARGS...` 同时托管非交互后台应用；交互式应用继续通过命令入口启动。已有同名服务不覆盖，新服务安装失败自动恢复，网关异常会触发整套后台运行环境重启。

开发验证已覆盖回环真实 SSH/SOCKS、Linux bwrap 命令入口与应用替换、真实 systemd 安装/重启/恢复、单元回归和独立安装；实际应用与用户浏览器的完整验收仍待完成。开发进度见 [闭环记录](docs/implementation/closure-status.md)。

## 为什么从主动风控角度做

每个建议都要说明：**想避免什么问题 → 本次观察到什么 → 证据支持到哪一步 → 做什么 → 如何复查。**

例如，浏览器和终端出口不同，首先意味着要在实际浏览器检测；单凭这个差异不要求用户换 IP。IPv6 请求失败意味着本次没连通，要确认关闭仍需检查配置。中文、时区、字体不会单独触发本项目的“风险判定”。

社区经验和公开政策帮助提出检查假设；它们需要来源、适用条件和可复现的验证。证据 Graph 留在研究与解释层，供追溯判断依据。

## 可选能力

已有能力全部保留。需要额外数据或遇到具体问题时，让 Agent 按需启用：

- **更多 IP 情报**：IPQS、AbuseIPDB、ipapi.is 等；[免费额度与 Key 配置](docs/archive/tutorials/providers.md)。
- **深入环境诊断**：WebRTC、DNS、浏览器属性与渲染、名单与连通性；[可选模块说明](docs/archive/tutorials/optional-modules.md)。
- **配置与维护**：支持的配置计划、恢复、归档和安装修复；[操作范围与复查](docs/archive/tutorials/environment-maintenance.md)。

## 数据与复用

报告在本机生成，Cookie、登录凭据和私人快照不上传聊天或检测网站。公网测量及 IP 情报查询仍会让对应服务看到请求 IP 或待查 IP；“本地”指采集与报告处理，不代表完全离线。[数据流说明](docs/reference/privacy.md)
